## 0. 产品定位与架构边界（2026-08 重定）

**对外一句话**  
生产执行型鞋业 ERP：接单能拍板、齐套不打架、计件能算清、排产能确认；  
不拼用友/金蝶总账；单据上对齐垂直「像鞋厂」，决策与报工上保持差异化。

**对标分层**

| 对手 | 怎么打 |
|------|--------|
| 小牛 / 云管家 / 泛普 | 补指令观感（流转卡）、算料、外发、箱唛；不做成功能清单型全盘翻刻 |
| 用友 / 金蝶 | 不拼总账 WMS；业务可对接财务 |
| 澜东等服装快反 | 只借插单/协同叙事，不当成鞋合刀标杆 |

**现有架构冻结（真合单闸门打开前）**

| 已定事实 | 产品含义 |
|----------|----------|
| 销售明细 → 生产单 **主路径 1∶1**（确认即建 `orders`） | 近中期主账；合批只挂多生产单，不改此关系 |
| **例外**：可存在无销售行的**独立生产单**（`sales_order_line_id` 空）；库层未做唯一约束 | 客供/出货回写/真合单迁移须显式处理；勿假定每张生产单都有销售行 |
| 齐套 / 领料 / 报工 / 捆标 / 排产认 **`orders.id`** | 合批 v1 **不**改为批次主体 |
| 出货认 **生产单** `shipments.order_id`（有销售行时经 1∶1 回销售） | 合批阶段足够；真合单须重做回写（见 §1.4） |
| 护城河：接单面 / 齐套池 / 排产 HITL / 计件 | 任何合批·合单不得削弱账本正确与 HITL |

**合执余分（长期正确，分阶交付）**

```text
长期正确：销售分账 + 指令可多来源 + 色码分配表（对齐多数厂与垂直趋势）
近端交付：单笔流转卡 →（其后）合批打印/组批 →（认领后）真合单
禁止：无分配硬合并；批次/合批直接出货；未认领的强制报工自动分摊
```

## 1. 优先级如何定义（重定）

### 1.1 原则（决策时按序想）

| # | 原则 | 含义 |
|---|------|------|
| 1 | 先像鞋厂，再聪明 | 卡/算料/外发/装箱空着，分析再亮也像通用制造 |
| 2 | 先守架构主账，再升级模型 | 1∶1 生产单未到闸门不拆；合批不得假装合单 |
| 3 | 先拍板闭环，再预测模型 | 今日行动/齐套日/风险条 → 再 ML |
| 4 | 双轨并行，轨 B 有硬序 | 决策(A)与单据(B)可平行，但 B 内有必保序（见 §1.3） |
| 5 | 关掉军师仍可用 | AI 只解释；确认与账本走 HITL/规则 |
| 6 | 明确不做写死 | P∞ 列表不可默默复活 |
| 7 | Agent 嵌在本系统 | 不做「第二套外挂业务库」；IM/OCR 是通道与增效，账本仍在本 ERP |
| 8 | 无量化不立项 Agent | 每个 Agent 增强须有可测的工时/损耗/延期/差错指标；业务岗验收 |

### 1.2 优先级代号

| 级 | 定义 | 进入条件 | 退出/完成标准 | 时间感 |
|----|------|----------|---------------|--------|
| **P0** | **本迭代必达**：半截能力收口或垂直快赢 | 已有数据/半截能力，或改动面小、现场一周可感 | 主路径可演示；有验收清单 | 当前 → 约 1 个迭代 |
| **P1** | **下一波必达**：高频 PMC/经营 + 垂直算料启动 | P0 主路径已可演示 | 按码 L1+L2 可用；催料/风险可执行 | 随后 1–2 迭代 |
| **P2-Must** | **垂直硬缺口必补**（顾问验货项） | P1 按码 L1+L2 已接齐套/采购，或并行但不挤占按码 | 外发闭环 + 箱唛主路径可演示 | 中期前段 |
| **P2-Next** | **增强**：合批、变更、IQC、门禁、方案卡 | P2-Must 已排期或明确不挡签约 | 各项独立验收；合批见 §4.2 | 中期后段 |
| **P3** | **认领制**：深分析 / 真合单 / 重主数据 | 有角色或客户书面认领；真合单另见架构闸门 | 闸门清单打勾再开发 | 后期 / 可选 |
| **P∞** | **不做或极后** | — | — | — |

> 旧称「P2」拆成 **P2-Must / P2-Next**，避免外发·装箱与合批抢同一「P2」带宽。对外仍可统称 P2，对内排期必须用细分。

### 1.3 轨 B 硬序（不可颠倒）

```text
B0 单笔流转卡 / 齐码发货
  → B1 按码用量（关键料）
    → P2-Must 外发 + 装箱箱唛
      → P2-Next 合批（组批+卡；领料仍分单）
        → P3 真合单（可产池+分配表；须闸门）
```

**例外：** 仅当合同验收写明「合刀/合批」且不要求真合单时，可将 **合批** 提前到与 P2-Must **并行**，仍不得插入 P0/P1 之前，也不得跳做真合单。

### 1.4 真合单架构闸门（B3c 开工前必勾）

未全部满足 → **禁止排开发**：

1. 客户/内部书面验收：需要「多销售来源 → 一指令」  
2. 设计通过：可产池（确认≠立刻建不可合并工单）  
3. 设计通过：色码级来源分配表 + 恒等校验  
4. 设计通过：**执行账本主体升级**（不只出货）：出货/可发按分配回写销售明细；并覆盖齐套池分配、领料、报工/`work_logs`、捆标、库存单据、应收等凡认单一 `order_id` 的链路——不能只改 `shipments.order_id`  
5. 设计通过：齐套/领料主体升到指令后的争料与接单冲击口径  
6. 迁移方案：存量 1∶1 单与独立生产单如何并存或升级

## 2. 总览

```text
P0 ──────── 轨A  今日3件事（必达）
           轨B  ①生产单流转卡  ②齐码可发货闸门

P1 ──────── 轨A  齐套预计日全链路 + 订单风险条 + 批价实绩
           轨B  客供收货台 + 不良→返修 + **按码用量 L1+L2（必达）**
           ※ 不合批、不合单

P2-Must ─── 轨B  外发工序单 + 配码装箱/箱唛
           （垂直验货第二刀；可与轨A门禁小项并行）

P2-Next ─── 轨B  合批 L1+L2（组批+合批卡；领料/报工仍分单）
                 + 变更版本 + 来料IQC + 补码向导
           轨A  放货回款提示 + 质量预警浅层 + 排产方案对比卡
                 + **IM推送/进度日报** + **实耗vs标准损耗预警**
           ※ 外协评分/催收挂 B2a 单据之上，不单独跳做

P3 ──────── 认领：真合单（闸门§1.4）+ 楦刀模/样品大货 + 真产能/WIP/质量根因等
           + **订单/来料 OCR 初稿（HITL 导入）**（有模板样本与业务认领）

P∞ ──────── 完整WMS、自研总账税务、大APS、订货会、鞋底专版、
           蒙特卡洛主UI、聚类自动派工、集体返修（政策前）、
           全物料×色×码 BOM 矩阵、无分配硬合并、合批直接出货、
           未认领的合批报工强制自动分摊、
           **AI裁断自动排版/全线视觉质检硬件、外挂第二套业务中台、私有化大模型必选、
           金蝶级制造费用全量分摊、NL2SQL写库、全能聊天改单**
```

## 4. 分阶段说明与定稿专节

### P0

- **必达：** A0、B0b、B0a。  
- **不做：** 按码全量、外发、合批/合单、sklearn、总账。  
- B0b 对象名统一为 **生产单**（`orders`），验收勿写模糊「订单」。  
- **B0a 可发口径（定稿）：** 色码可发量 = **约定工序**（默认末道）该色码合格累计 − 已出货；**禁止**把现有任意报工累加的 `order_items.completed_qty` 直接当「齐码可发」。闸门做在确认出货；草稿可否暂存由实现定，确认不可静默超可发。

### P1

- **必达核心：** B1c 按码 L1+L2（视为中等架构改动：需求行/齐套/采购可能变细，非纯 UI）。  
- **A1a 预计齐套日**宜在 B1c 接上齐套/采购之后或同迭代后半落地，避免按码料 ETA 仍按总双错算。  
- 轨 A 风险条/批价与客供/返修可与 B1c 并行。  
- **默认不合批、不合单**（例外仅 §1.3）。  
- 按码关键料所需的轻量码表/码段可随 B1c 做；完整楦/刀模档案仍属 B3a，不必等 P3 才允许码表。

### 4.1 按码用量（B1c）— 维持原拍板

| 档 | 范围 | 阶段 |
|----|------|------|
| L1 | 物料可标「按码用量」；大底等用码表/码段系数 | P1 必做 |
| L2 | 齐套/采购对按码料按码汇总 | P1 必接 |
| L3 | 按色维度 | P2-Next 视客 |
| L∞ | 全物料×色×码矩阵 | P∞ |

### 4.2 合批 / 合单 — 重定验收边界

| 档 | 内容 | 阶段 | 与现架构关系 |
|----|------|------|----------------|
| **L0** | 单笔生产单流转卡（=B0b） | P0 | 只读生产单色码/工序 |
| **L1** | 合批头：同款（默认同色）挂多生产单；成员+汇总色码 | P2-Next | 新表关联 `orders.id`；不改 1∶1 |
| **L2** | 合批流转卡打印；排产可按批筛选 | P2-Next | **领料、齐套承诺、报工、出货仍分生产单** |
| **L3** | 真合单：可产池+色码分配+多来源指令+出货按分配回写 | P3 | **破 1∶1**；须 §1.4 闸门 |
| **L4** | 批/指令码报工自动分摊 | P3 认领可选 | 默认不做 |
| **L∞** | 无分配合并；合批出货；未认领强制分摊 | P∞ | 禁止 |

**合批 v1 明确不包含：** 批次级领料、批次级齐套互斥、批次出货、默认自动分摊报工。  
（避免「空壳合批」争议：v1 交付的是 **组批协同 + 开裁纸面**，不是第二套账本。）

### P2-Must / P2-Next

- Must：外发、装箱——对齐小牛/云管家验货。  
- Next：合批及变更/IQC/门禁；**合批不得挤掉 Must。**  
- **Agent 增强（A2d/e/f）** 可与 Next 并行，但 **不得挤掉 B2a**；B2a+ 评分必须等 B2a 主路径可演示。

### 4.3 Agent 增强 — 从外部方案提炼的定稿（2026-08-09）

> 来源：行业「ERP+AI 外挂」方案。**吸收原则与场景，拒绝其架构前提**（弱 ERP + 第二套中台 + OCR 当一期主叙事）。

| 外部方案主张 | 本产品定稿 |
|--------------|------------|
| AI 外挂、ERP 不动 | **Agent 嵌本系统**；规则算数 + 军师解释 + HITL 写库 |
| 一期先做 OCR 录单证明 AI | OCR 为 **P3 认领**；一期价值看齐套/风险/排产/计件已有能力 |
| 计件工资 Agent 从零做 | **工资引擎已交付**；仅做 A2f 异常核对增强 |
| 金蝶级成本全量分摊 | **不做**（P∞）；最多直接成本异常可选 |
| 皮料 AI 自动排版 | **不做**；A2e = 标准损耗率 × 实耗对比规则预警 |
| 外协管控 Agent 纯软件先上 | **先 B2a 单据**，再 B2a+ 催收/评分 |
| 私有化大模型必选 | **不默认**；商用 API + 本地账本 + 脱敏即可 |

| **通过标准** | ① 分配表色码合计 = 指令色码 ② 抽走一来源后分配与卡可重算 ③ 出货后各销售欠数正确 ④ 齐套/领料/报工/库存/应收等认指令主体后争料与接单冲击口径有文档且演示不自相矛盾 ⑤ 存量 1∶1 与独立生产单可并存或已迁移 |
| **负面/不做** | 无分配硬合并；合批直接出货；只改出货表不改齐套/报工等 |
| **DoD** | 通用 DoD + 闸门文档归档（含全账本冲击面）+ 双客户同款合单一条端到端 |
