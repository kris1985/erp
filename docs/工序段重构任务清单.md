# 工序段重构 — 任务文件清单与验收标准

> **模型决策**：ProcessSegment 独立表，挂 Department（N:1，多部门可共用一段）；Team 冗余 segment_id；移除 ProductionLine。
> **UI 决策**：数据层统一，UI 层渐进披露——无班组模式 = 隐身默认组，代码零分支。

## 设计决策记录（讨论结论，实施依据）

| # | 决策 | 结论 |
|---|------|------|
| D1 | 工序段归属 | ProcessSegment 独立表；Department.process_segment_id 挂段（**无唯一约束**，支持针车一部/二部共用针车段） |
| D2 | 班组继承 | Team.department_id 已有；冗余 `segment_id` 快照，建组时由部门自动填入，不提供手动修改 |
| D3 | 报工/工资不受影响 | 计件粒度在工序级（process_id），单价在报工时锁入 WorkLog；段只是分组/统计维度，核心计价链路零改动 |
| D4 | 并行/串行 | **本次不实现**；`OwnProductLabor` 预留 `depends_on` 字段（只加字段，不用） |
| D5 | 部/线/组叫法 | 同一层的标签差异，通过 `team_label` 术语配置（部/线/组/班）实现全局文案替换，不建模 |
| D6 | 无班组租户 | `enable_teams` 开关；UI 上班组**整体消失**（非禁用）；数据层照常写 team_id（隐身默认组） |
| D7 | 默认组结构 | 按段各一组（截断组/针车组/成型组/包装组），不是一个全厂大组；结构：段部门→默认组 |
| D8 | 组织树 | 部门与班组统一在一棵树（「组织架构」页）；班组只能建在挂了段的部门下，段只读继承 |
| D9 | 派工对象 | 行业惯例：派工人（个人计件）或派组长（集体计件/组长分活）；**部门不是派工对象**，只做组织归属+统计 |
| D10 | 负责人 | Department 增加 `leader_id`（段负责人）；无班组模式下即"组长"，与隐身默认组 leader 同步；现有 is_leader() 逻辑零改动 |
| D11 | 三级创建入口 | 主入口=组织架构页树上新增；快捷入口=派工表单班组下拉底部「+新建」、员工页部门下拉底部「+新建」 |
| D12 | 升级路径 | 开启班组管理后隐身默认组可见化、改名、加组；历史数据按段归位，零迁移 |
| D13 | 个人/集体归属 | 个人/集体是**工序属性**（`ProcessDefinition.type`，在工序管理定）；工艺路线（OwnProductLabor）**不显示也不存储**该字段。当前代码已如此（模型无此列、保存时忽略、读取时从工序定义继承），但前端误放了可编辑下拉，本次移除 |
| D14 | 工序管理两属性 | 工序管理（MastersAdminView）的每道工序展示两个归属属性：**所属工序段**（segment）+ **类型**（个人/集体，已有 type 字段）；二者均为工序级、全租户统一，不随产品变化 |
| D15 | 排产算法零改动 | 排产引擎（`schedule_engine.py`）的产能模型、工序窗口、并行分组(band)、负荷跟踪、优先级评分全部按 `process_id` 级运作，不涉及段或产线。排产服务（`schedule_service.py`）的派工建议、集体工序校验、班组推断、确认草稿同理。**排产算法和服务代码不需要改动** |
| D16 | 齐套上下文结构约束 | `material_service` 的齐套上下文 `by_process` 列表**保持按 `process_id` 索引**不变（排产草稿行是工序级，按 process_id 索引最自然）；内部匹配逻辑从 `consume_process_id` 改为 `consume_segment_id`，但产出结构不变。排产服务消费 `by_process` 的代码零改动 |
| D17 | 进度展示层改动 | 进度计算逻辑零改动（completed_qty/plan_qty 仍在 OrderProcess 工序级）。仅需：①后端 process_progress 输出每项增加 segment_id/segment_name（从 P0 1.12 的 OrderProcess.segment_id 读取）；②前端 listProcessColumns 按 segment_id 分组（每段一列），listProcessText 按段聚合 completed_qty。段进度 = 段内各工序 completed_qty 之和 / plan_qty 之和 |
| D18 | **未分段语义（新增）** | `segment_id=null` = "未分段"。执行单/看板/进度展示加「未分段」兜底列（或并入首段展示）；派工按段过滤时未分段/无部门员工仅在「全部工人」下可见；工资/损耗报表 null 段归「未分段」 |
| D19 | **快照语义（新增）** | 所有冗余段快照（Team / OwnProductLabor / OrderProcess / WorkLog / OrderMaterialRequirement）= **创建时继承、不追改**；齐套校验（4.3/4.6）与订单用料统一读 `OrderMaterialRequirement.consume_segment_id` 快照，避免工序改段后新旧口径不一致 |
| D20 | **字段改名两期（新增）** | 本期：DB 旧列保留、API/前端字段名改用新（可回滚）；二期：确认稳定后清理旧列与旧引用（全库 136 处 consume_process / production_line 引用逐步收敛，见 C6） |
| D21 | **存量租户 enable_teams（新增）** | 迁移推断：该租户存在任意 Team（count>0）即 true，无班组才 false；6.4 默认 false 仅对新租户生效，存量有班组租户不退化（见 B4） |
| D22 | **成型段派工/报工（新增，竞品对齐）** | 成型段**不派工到人**，只排产到线/组（复用现有排产+班组）；**组长/统计员按线报产量**（单号×色码×良品数×不良数一次提交）；工人零报工动作。依据：竞品（小牛/云管家/鸿来）成型段均无个人派工，振东鞋业真实制度为"每日各线产量提报" |
| D23 | **四段报工差异（新增）** | 裁断/针车=**工人自主扫码报工（归属到个人）；派工/配额为可选软约束**（现状 `allow_unassigned_report` 默认开，未派工可报工，不动）；成型=**线级集体报工**（D22）；包装=**装箱即报工**（装箱数=产量，复用 packing_service）；报工统一按 segment 区分模式 |
| D24 | **集体分配=工资档案系数（新增）** | 成型集体报工复用现有 group 拆分链路：默认按 `Employee.skill_factor`（技能系数，`enable_skill_factor_split` 已有）拆分，派工行 `share_weight` 可覆盖；WorkLog 快照 `skill_factor_snapshot`（现有能力，零新增） |
| D25 | **逻辑批次（新增，竞品对齐）** | `ProductionBatch`：指令×型体×颜色×数量×状态，裁断建批；报工/不良挂 `batch_id`；**不建批次卡、不强制扫码**（竞品为流程卡/工位码粒度，无独立批次卡）；批次仅作排产/统计/追溯的聚合维度 |
| D26 | **质检独立于报工（新增）** | 不良拍照上报（复用 DefectEvent + rework 任务），**与报工分离**（竞品：小牛 IQC/IPQC/FQC、云管家不良品分布看板、特步全检/巡检独立反馈）；不良率/不良品分布进看板 |
| D27 | **筐码职责收窄（新增）** | 筐/捆码保留在**裁断/针车**（个人计件归因 + 追溯，现状）；**成型段退出扫码操作链**（履带混流无法归筐，竞品同），仅保留报工记录经 batch_id 的追溯关联 |
| D28 | **报工与质检分离（新增，机制1+2）** | 个人报工先行（产量/工资依据，快），质检**独立登记**不良（挂工序×时段×线组），**不阻断报工、不自动扣工资**；不良只做质量记录+看板，月结核减由管理员手工决定（竞品：RFID 工票产量/品质两套申报、特步报工与全检独立、小牛 IQC/IPQC/FQC） |
| D29 | **裁断/针车质检节点（新增）** | 裁断：完成入中仓前抽检；针车：合帮前/入面仓前中检（质量手册"每10双一捆打包及号码标识"）；不良登记挂工序×时段×线组，返修走现有 rework-tasks；本期不做按捆验捆（二期评估） |

## P7 — 成型段报工与批次（竞品对齐，新增）

### 设计说明（四段派工/报工对照，D22–D27）

| 段 | 派工 | 报工 | 计件 | 现状差距 |
|----|------|------|------|----------|
| 裁断 | 派到人（分包/筐） | 扫工位码/筐码报数量 | 个人 | ✅ 已有，不动 |
| 针车 | 派到人（捆） | 扫捆码/工位码报数量 | 个人 | ✅ 已有，不动 |
| 成型 | **只排产到线/组，不派到人** | **组长/统计员按线报产量**（单号×色码×良品数×不良数，一次提交） | 集体（skill_factor/share_weight 拆分） | ⚠️ 新增"线产量报工"，工资链路复用现有 group 拆分 |
| 包装 | 不派工 | 装箱即报工（装箱数=产量） | 集体/装箱联动 | ⚠️ 装箱联动（二期）；未启用退回线产量报工 |

成型段报工流程（一次提交 = 一个事务）：
```
① 组长/统计员（扫工位码可选）→ 选线/组 → 选单号 → 选色码
② 填：良品数 / 不良数（可选返修数）
③ 确认 →
    · group WorkLog：qty=良品数，成员=该线组，按 skill_factor/share_weight 拆分（复用 report_service 现有链路）
    · 不良数≥1 → DefectEvent（挂 batch_id/线/时段，进不良筐登记）
    · 返修数>0 → 自动建返修任务（复用 rework-tasks 流程）
    · 配额校验：该线该单该色码累计 ≤ 计划数（复用 _enforce_quotas）
    · 批次状态 → confirmed
```
