# 生产单风险与排序试算算法说明

## 1. 文档目的

本文记录生产单页面当前采用的决策指标、风险计算、异常判断、排序试算和前端交互规则，作为后续开发、测试、验收和算法调整的共同依据。

本文描述的是当前已经实现的逻辑，不代表完整 APS 优化模型。当前排序算法仍以交期和物料风险试算为主，暂未计算换款、换色、换楦、换线和多产线并行造成的效率变化。

## 2. 页面决策信息

生产单表格保持原有业务列，只增加一列“风险”。表格上方显示以下摘要：

- 必延期：当前预测完成日期超过交货日期，或交货日期已过但生产单尚未结束。
- 高风险：存在关键缺料或计划进度明显落后，但尚未确定延期。
- 进度落后：截至今天的应完成数量明显高于实际完成数量。
- 未派工异常：当前工序已经满足开工条件，但没有任何人员派工。
- 缺料：BOM 非空且齐套结果为否。
- 未来 7 天交货：交货日期处于今天至今天后第 7 天，包含首尾日期。
- 超负荷工序：不单独占用摘要卡片，显示在“产能优化 · N处超负荷”按钮中。

风险、进度落后、未派工异常、缺料和未来 7 天交货均可作为列表筛选条件。摘要统计基于全部未结束生产单，不受当前分页影响。

生产单列表默认使用“未完成”状态，包含待生产和生产中，不展示已完成、已取消。后端内部的 `cut`（已执行开裁动作）与 `in_progress` 统一作为页面上的“生产中”；选择“生产中”时使用组合条件查询两种内部状态。用户仍可单独查看已完成、已取消，也可以选择“全部”查看所有状态；再次进入页面时恢复为“未完成”。

顶部状态统计接口始终返回精确整数。前端对小于 10,000 的数量使用千分位完整显示；达到 10,000 后使用“万”缩写，并通过 Hover 展示精确数量。状态区域允许自动换行，避免大数量或较窄屏幕造成横向溢出。

订单管理页面的状态统计和筛选以订单明细为主数据，数量单位为“条产品明细”。订单号、客户来自订单头；品牌、客户型号、工厂型号和状态必须在同一条明细上同时满足。生产单状态通过业务事件写回订单明细：生成生产单为 `scheduled`（待生产），开裁或开始报工为 `in_production`（生产中），生产完成为 `completed`，未开工生产单撤回后恢复为 `pending`（待排产）。订单列表查询不再临时关联生产单推导明细状态。

## 3. 风险等级

风险等级由低到高排列：

1. `normal`：正常。
2. `attention`：关注。
3. `high`：高风险。
4. `late`：必延期。

当一张生产单同时满足多个条件时，保留最高等级，同时在 Hover 浮层中展示全部风险原因。

### 3.1 已结束生产单

状态为 `completed` 或 `cancelled` 时直接返回“正常”，建议为“无需处理”。这类生产单不参与顶部未结束生产单风险统计。

### 3.2 必延期

满足以下任一条件：

- 存在预计完工日期，并且预计完工日期晚于交货日期；
- 交货日期早于今天，并且生产单尚未完成或取消。

预计延期天数：

```text
预计延期天数 = 预计完工日期 - 交货日期
```

### 3.3 高风险

尚未判定为必延期，但满足以下任一条件：

- BOM 非空且物料未齐套；
- 任一未完成工序的进度落后超过容差。

### 3.4 关注

没有更高等级风险，但满足以下任一条件：

- 距离交期 0 至 7 天，且生产单仍有剩余数量；
- 当前工序已经满足开工条件，但没有人员派工；
- 尚有剩余数量，但没有预计完工日期。

## 4. 预计完工日期

生产单预计完工日期取所有工序计划结束日期中的最大值：

```text
预计完工日期 = max(工序计划结束日期)
```

当前工序取工艺路线中第一道尚未完成的工序。前端 Hover 同时显示预计完成日期、相对交期的提前或延期天数、当前工序和生产单剩余数量。

## 5. 进度落后算法

### 5.1 适用范围

逐道检查尚未完成的工序。当前实现按自然日线性推算计划完成数量，暂未扣除节假日、停工日或每日非线性爬坡。

### 5.2 应完成数量

如果工序计划结束日期早于今天：

```text
应完成数量 = 工序计划数量
```

如果今天位于计划开始和计划结束日期之间：

```text
计划总天数 = 计划结束日期 - 计划开始日期 + 1
已过天数 = 今天 - 计划开始日期 + 1
应完成数量 = round(计划数量 × 已过天数 ÷ 计划总天数)
```

其他情况应完成数量为 0。

### 5.3 落后数量和容差

```text
落后数量 = max(0, 应完成数量 - 实际完成数量)
容差 = max(3 双, round(计划数量 × 10%))
```

只有当“落后数量 > 容差”时，才判定该生产单进度落后，避免小数量报工时差造成频繁误报。

风险详情示例：

```text
针车应完成约 180 双，实际 132 双，落后 48 双
```

## 6. 未派工异常算法

只检查当前工序，不统计所有未来工序。

当前工序满足以下任一开工条件时，应当存在派工：

- 工序有计划开始日期，且计划开始日期不晚于今天；
- 当前工序不是第一道工序，并且上一道工序已经完成。

如果满足开工条件，同时该工序的派工记录数量为 0，则判定为未派工异常。

这一定义避免把尚未到计划时间的未来工序错误统计为异常。

## 7. 缺料算法

生产单满足以下条件时计为缺料：

```text
BOM 非空 AND kit_ok = false
```

风险详情展示缺料项数。排序试算时还会计算“必须到料日期”：

```text
必须到料日期 = 调整后的开裁开始日期
```

当前排序试算不会自动等待物料预计到料日，只提示缺料生产单最迟必须何时到料。

## 8. 超负荷工序算法

统计窗口为未来 14 天。

系统按工序聚合每日负荷，并结合工序单人日产能、有效人数和效率系数得到每日可用产能。满足以下条件的工序计为“超负荷工序”：

```text
未来 14 天内 over_capacity_days > 0
```

顶部不单独增加卡片，而是在产能优化按钮显示：

```text
产能优化 · N处超负荷
```

进入工序产能优化建议后，根据峰值利用率、超载天数和现有人数给出加人、加班、维持、减人或补充产能配置建议。

## 9. 排序试算算法

### 9.1 当前实现

生产单拖拽后不会立即写数据库。前端进入“排序尚未生效”状态，并在 300ms 防抖后调用试算接口。

后端按照拖拽后的生产单顺序逐张处理：

1. 读取原有工序时间窗；
2. 从队列游标日期开始平移该生产单全部工序窗；
3. 当前生产单的新完工日期后移一个工作日，作为下一生产单的开始游标；
4. 计算新旧开工日期、新旧完工日期、顺延天数和交期风险；
5. 缺料生产单补充必须到料日期。

当前队列是串行模型：

```text
下一单开始日期 = next_workday(当前单完工日期 + 1 天)
```

### 9.2 试算结果

每张生产单返回：

- 原开工日期、新开工日期；
- 原完工日期、新完工日期；
- 相对原排程的顺延天数；
- 是否超过交期；
- 物料是否齐套；
- 缺料项数；
- 必须到料日期；
- 新顺序下的风险等级、原因和建议；
- 新工序时间窗。

汇总返回：

- 受影响生产单数量；
- 存在交期风险的生产单数量；
- 缺料生产单数量。

### 9.3 前端合并规则

排序试算风险不会覆盖生产单原有的进度落后、未派工异常等风险。前端合并基线风险与试算风险：

- 风险等级取两者中较高者；
- 风险原因按 `code` 去重后合并；
- 建议采用较高等级风险对应的建议；
- Hover 标记“按当前未生效排序试算”。

### 9.4 连续拖拽和并发保护

- 连续拖拽使用 300ms 防抖，避免每次鼠标落下都立即请求；
- 新请求会使旧请求结果失效，避免旧试算覆盖新顺序；
- 拖拽只修改前端顺序，不直接保存；
- 点击“完成调整”后统一查看影响；
- 点击“确认生效”才调用确认接口；
- 确认接口重新检查原始顺序，发现其他生管已修改时拒绝覆盖；
- 排序序号和新工序窗在同一事务中写入，失败时整体回滚。

## 10. 接口

### 10.1 生产单列表

```text
GET /api/v1/executions
```

新增筛选参数：

- `risk_level=normal|attention|high|late`
- `exception_type=progress_lag|unassigned`

列表行新增 `risk`：

```json
{
  "level": "high",
  "label": "高风险",
  "projected_finish": "2026-08-31",
  "delivery_delta_days": 0,
  "current_process": "针车",
  "remaining_qty": 158,
  "progress_lag": true,
  "unassigned_exception": false,
  "reasons": [
    {
      "code": "progress_lag",
      "label": "进度落后",
      "detail": "针车应完成约 180 双，实际 132 双，落后 48 双"
    }
  ],
  "recommendation": "核实瓶颈并调整人员或顺序"
}
```

### 10.2 顶部摘要

```text
GET /api/v1/executions/risk-stats
```

返回全部未结束生产单的风险等级数量、缺料数、未来 7 天交货数、进度落后数、未派工异常数和未来 14 天超负荷工序数。

### 10.3 排序试算

```text
POST /api/v1/executions/reorder/preview
```

请求体：

```json
{
  "ordered_header_ids": [12, 8, 19]
}
```

该接口只读，不修改数据库。

### 10.4 确认排序

```text
POST /api/v1/executions/reorder/confirm
```

请求体同时携带最终顺序和拖拽开始时的基线顺序。后端先进行并发校验，再重新试算并原子写入。

## 11. 当前限制

当前算法尚未覆盖：

- 同款、同色、同楦连续生产带来的效率收益；
- 换款、换色、换楦、换线时间；
- 多产线和多班组并行排程；
- 物料预计到料日对实际开工的自动约束；
- 工作日历下的工序应完成数量曲线；
- 新款爬坡、返工、设备停机等动态效率；
- 上下工序节拍差和在制品峰值；
- 历史实际产量对工时和效率参数的自动校准。

因此，当前风险结果用于辅助生管发现异常和评估手工排序影响，不应被解释为自动最优排程结论。
