# 产品决策：中小鞋厂实情 × 竞品排产参数 → 值得加什么

> **角色：** 产品经理综合判断  
> **输入：** 中小成鞋 OEM 现场约束 · 竞品参数族（[`competitive-merge-schedule.md`](./competitive-merge-schedule.md) §9）· 现网 `schedule_settings` / APS 整合稿  
> **日期：** 2026-08-09

---

## 1. 中小鞋厂「计划」真实情况（决策前提）

| 现实 | 对参数设计的含义 |
|------|------------------|
| PMC 往往 1～2 人，兼跟单，不会养 APS 专员 | **常调旋钮 ≤ 8 个**；超过就退回 Excel |
| 主数据半残：BOM/工时凭经验，楦模台账常不全 | 依赖细主数据的参数（换型矩阵、机台小时）**配了也假** |
| 最大痛是缺料停工 + 急单乱插 + 合刀靠吼 | 参数应服务齐套、交期窗、插单可解释，不是最优求解 |
| 产能凭「成型一天多少双」口头数，很少到机台班次 | **日产能（双/天）够用**；班次时刻表是过度设计 |
| 旺季必加班、法定假有时也赶 | 需要「非工作日能否排」一眼开关，不必先上完整厂历 |
| 外发常见但系统常无外发单 | 外协产能参数 **无单据就先别做**（B2a 后） |
| 计件按生产单，怕合糊涂账 | 合批只荐不合账；参数不诱导「自动合并落库」 |
| 信纸面与确认感，不信黑盒 | 多方案 + HITL > 自动最优；参数要能解释进方案话术 |

**产品原则：** 只加「配了就会改 PMC 行为、且不依赖虚假主数据」的参数；其余进主数据建设或二期认领。

## 2. 竞品参数族 → 值不值得加（总表）

|------------|-------------------|------------|------------|----------|
| 策略：交期/产能/齐套；正倒排 | 极高 | 低 | ✅ 已有三策略 | **已有，守住讲清** |
| 急单 / 简单优先级 | 极高 | 低 | ✅ `is_rush` | **已有**；可选补客户等级轻权重 |

| 工序/全局日产能 | 高 | 低（可估） | ✅ 已有 | **已有**；实施引导填关键瓶颈即可 |

| 负荷上限预警（如 ≥90% 高亮） | 中 | 低 | 有负荷，阈值可配 | **值得加（轻）** |
| 厂休日/维保例外日历 | 中 | 低 | 无 | **有条件加**（加班开关之后） |
| 客户等级权重 | 中 | 低 | 弱 | **有条件加**（有客户分级字段再开） |
| 计划锁定（确认单不被自动挤） | 中 | 低 | 草稿/确认模型可延伸 | **有条件加**（插单多了再做） |
| 楦/刀模/底模约束 | 中（部分厂高） | **高** | B3a 未上 | **有条件加**：先档案，再提示；不作排产硬参数 |
| 外协周期/外协产能 | 高（外发厂） | **高（要 B2a）** | 无 | **有条件加**：单据后 |
| 班次起止、开动率、机台小时 | 宣传高、现场低 | 高 | 无 | **不加** |
| 换型矩阵 / 换模分钟优化 | 叙事强 | 高 | 无 | **不加**（精 APS） |
| 技能矩阵、人数出勤进排程 | 低 | 高 | 人事未闭环 | **不加** |
| 十几种分派规则组合 / 危急比引擎 | 低 | 中 | 三策略够 | **不加** |
| 产能缓冲 % 自动留白 | 中（概念好） | 低 | 可用紧天数/负荷预警近似 | **暂不加**；用负荷预警代替 |

| 生产可用库存与实仓分离（华软向） | 中（防抢料） | 中 | 齐套池承诺已近似 | **不加新参数**；讲清池模型即可 |

## 3. 值得加的清单（按优先级）

### P0 — 行为收口（不全是新配置项，但比新旋钮更值钱）

| # | 项 | 为何值得 | 形态 |
|---|-----|----------|------|
| 1 | 齐套日/ETA **硬卡**计划开工与确认 | 中小厂第一痛是缺料停工；竞品都讲齐套闸门 | 引擎约束 + 确认闸门（已列 P0-1/2） |
| 2 | 引导配置 **瓶颈工序日产能** | 无产能则负荷/保现场策略空转 | 实施清单 + 设置页提示，不必新字段 |

### P1 — 新参数 / 小能力（建议进设置页「计划参数」）

| # | 参数 | 默认建议 | 用户价值 | 开发体量 |
|---|------|----------|----------|----------|
| 1 | `allow_schedule_on_non_workdays` | `false` | 旺季加班一眼打开；否则假日永远排不进 | **本波必做** |
| 2 | `schedule_blackout_dates`（停工日列表） | `[]` | 厂休/停电/长于国定的春节厂休；算工作日时跳过 | **本波必做（轻量）** |
| 3 | `merge_delivery_window_days` | **`7`** | 合批推荐/筛选核心旋钮 | **本波必做**（随 P1-6） |
| 4 | `merge_require_same_color` | `true` | 与 B2f 一致，可配置放开 | 随 P1-6 |
| 5 | `merge_min_qty` | `0`（或实施改 300） | 减少碎单推荐噪音 | 随 P1-6 |
| 6 | `merge_block_locked_orders` / 客户禁合 | 按标记 | 外贸分批、品牌单 | 有标记则做 |
| 7 | `load_warn_utilization` | `0.9` | 负荷≥90% 高亮 | 建议本波 |

**P1 体验配套（已确认必做）：** **P1-6 合批自动推荐 HITL** + P1-4 排产池按批筛；与 P0 **并行**。跨款同料合刀 **不进 v1**。

**停工日 vs 加班开关：** 停工日优先——即使允许非工作日排产，黑名单日期仍不排（本波不做「停工日强制开工」例外）。

### P2 — 有条件再加（主数据或单据就绪）

| # | 项 | 触发条件 |
|---|-----|----------|
| 1 | 班次/循环维保规则 | 停工日列表不够用时再升级 |
| 2 | 客户等级影响排序权重 | 客户主数据有稳定等级 |
| 3 | 已确认计划「锁定不被挤」 | 插单仿真使用频繁、抱怨被冲掉 |
| 4 | 同楦/同底模进入合批推荐 | B3a 覆盖率 ≥95% |
| 5 | 外协周期进倒排 | B2a 外发单可跑通 |

### 明确不进近中期路线图

班次时刻表、开动率、换型矩阵、技能矩阵、危急比规则引擎、甘特、自动重排落库、Nesting、模具独占 APS、独立「生产可用库存」第二套账、**演示模式/禁 confirm 开关（已确认不做）**。

## 4. 建议的「常调面板」最终形态（给 PMC 看的）

中小厂打开「排产/合批设置」只应看到类似：

```text
【怎么排】
  ○ 保交期  ○ 保现场  ○ 只排齐套先

【日历】
  ☐ 允许在周末/法定假排产（加班模式）
  停工日：【维护列表】厂休 / 停电 / 其它（这些天一律不排）

【产能】
  默认日产能：____ 双/天
  关键工序产能：（成型/裁断…）

【风险】
  交期剩余 ≤ __ 天标「偏紧」

【负荷】
  利用率 ≥ __% 预警

【合批推荐】
  交期相差 ≤ __ 天可建议合批（默认 7）
  ☑ 必须同色   最小合计 ____ 双
  ☑ 未齐套不参与推荐
```

其余策略结果用方案卡/军师解释，不堆高级页。

## 6. 产品结论（可直接评审）

1. **中小鞋厂不缺参数字典，缺的是少数旋钮真能改计划行为。**  
2. **近端必做配置：** 加班可否排非工作日、**停工日列表**、合批交期窗（默认 7）+同色/最小量、负荷预警；外加齐套日硬约束与 **P1-6 合批推荐**。  
3. **楦/外协/锁单** 有条件加，绑 B3a/B2a 与使用反馈。  
4. **竞品长尾 APS 参数多数不值得加**——会抬高实施成本、放大脏数据，且违背「可确认粗排」定位。  
5. **合批自动推荐与排产同屏、同交期窗参数**——相对「仅人工勾选合批」的正确补强，不是上合单。  
6. **演示禁 confirm 开关本波不做。**

## 7. UI 备注（与合批入口决策对齐）

合批**计划主入口在排产池**（推荐/交期窗/按批筛）；生产订单保留组批与打卡为**执行辅入口**。  
详见 [`merge-batch-aps-alignment.md`](./merge-batch-aps-alignment.md) §12 · [`B2f-merge-batch.md`](./B2f-merge-batch.md) §2.1。  
合批相关参数消费方在排产/计划设置，而非仅挂在订单列表。
