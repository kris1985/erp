## 一、项目定位（一句话，无噱头 AI）

作为**现有 ERP 内置能力**（待排池 / 出方案 / 草稿确认已可演示），配套车间军师等 Agent：AI 只做校验、预警、模拟、归纳与报表；**所有计划必须 PMC 人工审核确认后落库**。

优先解决：**缺料停工、交期失控、人工改 Excel 加班、瓶颈工序过载看不清**。  
不做：纯展示大屏、高成本视觉排版/质检、无人自动下发排产。

**对内补一句（技术必讲）：** 一期不是「从零做 APS」，而是**收口已有齐套 + 规则排产**，补齐套日约束与周负荷体验；模具 / 外协进排产分别挂 B3a / B2a。

**对外分阶段同步（售前必讲，防交付落差）：**  
一期粗周排是**基础投产规划**（齐套闸门 + 可确认方案）；**楦头冲突校验、外协自动分流**属二期精细化增值，须主数据 / 单据达标后才开做——交付前书面同步客户分阶段上线计划，禁止销售口头承诺「一期就能自动算楦头、自动分流外协」。

## 二、落地两期（对外节奏 × 对内范围）

### 一期 · 收口 MVP（建议 30 天内可验收演示）

**对外一句话：** 物料齐套校验 + 周粗排产上线，缺料提前看得见，PMC 从改表变为确认方案。

| 对外可讲 | 对内必交付（做 / 改） | 不进一期必交付（挂 / 砍） |
|----------|----------------------|---------------------------|
| 齐套：用料×库存×在途，缺料清单 + 最早可开工日 | **改** 齐套日 / ETA 三处口径统一；**改** 生产单计划窗口**不得早于**齐套日 | 时间维经典 MRP / 计划订单（砍） |
| 粗排：工单池、倒排/正排/齐套策略、负荷预警、人工调计划 | **已有** pool / proposals / 草稿确认 / 插单仿真 / A2c 对比卡；**改** 周负荷汇总视图；**改** 「今日可排」一键出方案 | 以「成型线对象」建档排程、甘特拖拽（砍）；外协周发料计划（挂 B2a） |
| 主数据：BOM、工艺工时、产能、规则 | **已有** BOM/工艺/工序日产能配置/三策略；客户侧补录准确度 | 一期强制模具台账、外协厂产能档案、换模分钟主数据（挂或砍约束） |
| 输出：周计划感、备料/缺料可见、消息提醒 | **改** 缺料/风险进今日行动与推送加深（A2d）；**改** 缺料批量导出（P1-5） | 完整「裁断备料单 + 外协发料单」单据包（外协挂 B2a；备料用现有缺料/采购建议） |

**一期价值口径（老板可感知，报表可统计，不另增算法）：**

| 类型 | 指标 | 说明 |
|------|------|------|
| 业务价值 | PMC 周计划编制：从多表拼改变为「选池 → 出方案 → 确认」，**操作步骤目标减少约 60%** | 上线前后各抽 1～2 周对照步骤/耗时即可，不绑死合同罚款 |
| 业务价值 | 缺料停工预警**提前 ≥3 天**出现在工作台「今日行动」，跟单无需手工筛缺料工单 | 依赖 ETA/齐套日；与 P0 口径统一配套 |
| 慎签合同 | 齐套准确率 98%、负荷误差 5%、工时降 70% | 除非另附抽检样本与基线协议 |

**一期验收（硬性）：**

**功能 / 一致性**

1. 同生产单：缺料 / 齐套相关页 / 风险条上的齐套日或 ETA **一致或明确无 ETA**  
2. 缺料卡住的单：**不会**排出齐套日前开工的确认计划（有自动化测试更佳）  
3. 路径可走通：待排池 → 出方案（含对比头）→ 采纳草稿 → PMC 确认落库  
4. 能回答「本周 / 下周瓶颈工序是否超载」（周负荷视图）  
5. 缺料工单可批量筛选导出 Excel（款号、缺料物料、预计齐套日、风险等级），并可推送企微给采购/跟单（P1-5）

**业务感知（抽检即可）**

6. 工作台今日行动中，缺料类行动带预计齐套日 / ETA，覆盖「未来 3 天内可能断料」样本  
7. PMC 出一份周计划的主路径步骤数较上线前 Excel 流程明显缩短（目标约 60%，记录基线后对比）

### 二期 · 增效（有启动判定才进 Backlog，不按「30 天甘特 APS」打包）

**对外可讲方向：** 负荷更可信、异常能重算建议、外协/合批更深、看板更好用。  
**对内红线：** 不上机台小时甘特、模具独占全自动排程、无人全表重排落库。

| 方向 | 启动判定 / 前置 | 做什么 | 不做什么 |
|------|-----------------|--------|----------|
| 负荷与交期更准 | 报工数据可抽检 | 真产能校准建议、风险根因进军师/今日行动 | 利用率 +10% / 延期 −30% 进合同 |
| 外协进倒排与催收 | **B2a 启动标准见 §2.1** | 外协周期进计划；催收/评分（B2a+） | 无单先做外协评分看板 |
| 楦 / 刀模冲突提示 | **B3a 启动标准见 §2.1** | 抢楦冲突**提示** | 楦模资源独占 APS |
| 合批损耗差值 | **§2.2** 实耗回写达标 | 排产按批筛；合批 vs 拆批损耗差值 | AI 自动裁断排版 |
| 异常调度 | 一期收口完成 | 异常 → 列出受影响单 → **人点**重算；有余力上预计算兜底（P1-备选） | 「5 分钟无人自动改全厂排程并落库」 |
| 车间闭环 / 看板 | 现有报工与派工 | 确认后派工列表/打印；角色看板加深 | 四套经营大屏堆砌 |

#### 2.1 「挂」类启动判定（B2a / B3a）

未达标准**不排开发资源**；达标后由实施顾问出具核对表签字，纳入二期 Backlog。

| 项 | 启动标准 | 纳入后做什么 |
|----|----------|--------------|
| **B2a 外协进排产** | 客户外协相关主数据 + 外发业务流程可跑通；外协单据 / 外协厂档案等实施核对完整率 **≥95%**，顾问签字 | 外协周期进倒排、周发料/催收评分等 |
| **B3a 楦刀模冲突提示** | 在产主力款楦 / 刀模 / 大底模具档案覆盖率 **≥95%**，数量与款绑定可抽检，顾问签字 | 冲突提示（仍非独占 APS） |

#### 2.2 合批损耗差值「挂」的前置（写清依赖）

合批损耗分析依赖：**裁断每日领料 + 完工报工实耗完整回写**。  
报工 / 领料闭环在客户侧稳定跑通并可抽检后，再启动开发；**不占用一期排产收口资源**。

**二期验收：** 以「可落地派工、异常重算建议可追溯、外协/楦达标后提示有效」为准；商业提升数字单独立基线后再谈。

## 三、排产输入（分层）

### 开发侧：A 挡承诺，B/C 不挡一期研发

| 层 | 含义 | 内容 |
|----|------|------|
| **A** | 缺则不承诺齐套 / 交期指标 | 订单色码交期优先级；BOM/损耗/工艺路线/工序天数；库存+在途 ETA；排产策略与齐套闸门 |
| **B** | 无则降级运行 | 关键工序日产能、合批备注、租户停工日历 |
| **C** | 挂后续 | 机台/成型线细档、换模、楦套数、外协产能（先 B2a/B3a） |

### 实施侧：投产上线闸门（刚性）

**交付顺序约束：**

1. 完成排产数据核对表（原 42 项清单，按客户业态可裁剪）验收签字；  
2. 方可开启客户侧排产模块**正式投产**调试与确认落库权限放开；  
3. **数据不达标：仅开放演示模式**（可看出方案 / 讲解），**不允许**作为现场正式排产工具日常使用。

> 与「不挡我方一期开发」不矛盾：研发可在演示租户推进 P0/P1；**客户生产环境**必须过核对表。

## 四、技术集成约束（红线）

| 红线 | 现网态度 |
|------|----------|
| 排产 / AI **无**自动改交期、自动下发、自动建采购单的权限 | 已守：方案 → 草稿 → 确认才写工序日期 / 派工 |
| 写入仅 PMC（或授权角色）确认后生效 | 已守 |
| 大模型只做问答 / 归纳；**主运算 = 规则引擎** | 已守：`schedule_engine` + 军师工具白名单 |
| 嵌入现有 ERP，不独立系统、不单独登录 | 已守：`/admin/schedule`、`/admin/schedule-assistant` |
| 成本 / 采购价权限隔离；调整留痕 | 延续现有权限与日志策略 |
| 禁止高价视觉裁断排版、产线视觉质检作排产配套 | 路线图 P∞ |
| **实施：核对表未签字不得正式投产启用排产确认** | 见 §三 · 实施侧 |

> 本产品自身即账本：确认前只建议、确认后写本库（等同「外挂只读 + 确认回写」原则）。

## 七、隐性风险与补强（开会直接讲）

| # | 风险 | 补强（已写入本文） |
|---|------|-------------------|
| 1 | 「挂」无启动标准，二期无限期或被提前插队 | §2.1：完整率 ≥95% + 顾问签字才进 Backlog |
| 2 | 售前按愿景承诺楦/外协，一期落差客诉 | §一：分阶段话术；销售禁承诺一期自动算楦/分流 |
| 3 | 砍掉全自动重排后，人点重算等待差 | P1-备选：预计算缓存，仍 HITL |
| 4 | 验收只像功能演示，老板无感 | §二：步骤约 −60%、缺料提前 3 天进今日行动 |
| 5 | 合批损耗「挂」但依赖不清 | §2.2：领料+实耗报工闭环后再做 |
| 6 | **插单预览与落库不同步**：`simulate_insert` 是预览——`delivery_first` 锚定日期只标"产能不足"风险不挪日期（allow_shift=False），`capacity_first` 插单置后不影响前单；**真正移动已排单日期的是急单确认落库（`_apply_rush_impact_locked`）**。PMC 可能看到预览"未挤其它单"、确认后却动了已下发窗口（联合场景验证见 [`schedule-workforce-actual-capacity.md`](./schedule-workforce-actual-capacity.md) §八） | UI 话术"预览看风险、确认才动单"；确认前二次展示实际被移动的已排单清单（gantt-rush/confirm 已展示 impacts，补一句"将移动已下发窗口 N 张"）；不做静默移动 |

**避坑短句：**

1. 不搞全自动无人排产。  
2. 不做视觉排版/质检挂靠本项目。  
3. 研发不挡、投产要闸——演示模式 ≠ 正式启用。  
4. 先粗排收口，二期按启动判定立项。  
5. 对外可叫 APS，对内交付是「可确认粗排 + 齐套闸门」。
6. 插单预览看风险、确认才动单——别让 PMC 把"预览未挤"当成"确认不会挤"。

## 八、评审结论（会议签字栏 · 可直接复制）

1. 本对照清晰区分**对外产品愿景**与**一期实际开发范围**，存量功能最大化复用，新增开发仅聚焦 **P0 / P1** 核心痛点，研发投入可控、上线风险低。  
2. 严格执行 **HITL** 人工确认落库，禁止 AI 自动调整生产计划、采购单据，规避工厂业务风险。  
3. 精细小时级 APS、模具独占、全自动重排等高成本功能全部后置；待客户主数据（外协 / 楦刀模）按 **§2.1** 达标后纳入二期迭代，**不提前排开发资源**。  
4. 开发任务绑定现有接口、页面、服务，拆解清晰；验收含一致性演示 + 简易业务量化（今日行动缺料提前可见、PMC 路径缩短），可抽检。  
5. 实施前置：**核对表验收签字前仅演示模式，签字后方可正式投产使用排产确认**，从源头降低因数据缺失导致计划失效的风险。  
6. **评审通过：一期 Backlog 仅执行 P0 / P1（含 P1-5；P1-备选视余力）；标记「砍 / 挂」的功能不纳入本期开发排期。**

## 十、产品 × 架构决策记录（需求满足度 · 可落地性）

> 记录日期：2026-08-09。供评审后复查，避免口头结论丢失。  
> 问题 1：能否满足大部分鞋厂需求？→ **产品**  
> 问题 2：这套智能排产能否工程落地？→ **架构**

### 10.1 总判（一并回答）

| 角色 | 一句话 |
|------|--------|
| **产品** | 能满足**大部分中小成鞋 OEM** 的排产决策痛点（齐套、周先做谁、插单冲击）；**不能满足**「日甘特 / 楦独占 / 自动全厂重排」类期望，也暂难满足**外协很重**或**抢楦很狠**的厂。 |
| **架构** | **能落地**——主路径已在现网（引擎 → 草稿 → HITL 写库）；一期是补硬约束与体验，不是从零造 APS。会失败的路径是范围胀成精 APS，或齐套日未进硬约束就开放正式确认。 |

**对外卖点必须锁死：**「齐套 + 可确认粗排」，不卖「完整 APS」。  
**对内交付必须锁死：** 整合稿 P0/P1；精 APS / 自动落库重排不进迭代。

### 10.2 产品：谁够用、谁不够（分群）

| 工厂类型 | 满足度 | 记录要点 |
|----------|--------|----------|
| 单厂、本厂工序为主、PMC 仍 Excel、痛点缺料+交期 | **高（约 7～8/10）** | 主战场；一期收口后可替代周计划 Excel |
| 外发占比高（针车/复合大量外协） | **低（约 4～5/10）** | 无 B2a 则排产只覆盖本厂半截；**满足度上限**在外发单，不在排产 UI |
| 多款抢楦 / 刀模大底周常冲突 | **低～中** | B3a 前不能当资源约束；调研须问清是否周常 |
| 要小时甘特、换模优化、无人重排 | **故意不满足** | 非「大部分」数量；追了会拖垮实施与架构 |
| 品牌多组织 / 鞋底专版 | **非靶心** | 见竞品对照与路线图 P∞ |

**大部分鞋厂真正要的四件事（产品验证清单）：**

1. 料齐没有、最早哪天能上 → 齐套池 + 齐套日  
2. 这周先做谁、急单撞谁 → 粗排 + 插单仿真 + HITL  
3. 谁拖交期、缺料谁跟 → 风险条 / 今日行动  
4. 计划与现场别两张皮 → 报工 / 派工 / 确认写日期  

**产品侧已登记风险（杀伤力序）：**

| ID | 问题 | 影响 | 处置（已写入前文） |
|----|------|------|-------------------|
| PM-1 | 外发未进排产 | 外协厂说「不像鞋厂排产」 | 挂 B2a；§2.1 ≥95% 启动 |
| PM-2 | 售前按愿景承诺楦/分流/甘特 | 一期交付客诉 | §一 分阶段话术；销售禁承诺 |
| PM-3 | BOM/库存/在途差 | 「排产不准」归因产品 | A 层挡承诺；投产核对表闸门 |
| PM-4 | 抢楦未建模 | 部分厂周计划仍靠吼 | 挂 B3a；先提示后独占 |
| PM-5 | 合批/算料信任不足 | 不敢按系统排 | 按码已补；损耗挂 §2.2 |

**产品策略记录：** 一期把 P0/P1 做透；**尽快让 B2a 成为可售二期标配**（把「大部分」里外协厂从不够拉到够用）；精 APS 可以一直不碰。

**对外口径（备案）：**  
> 我们解决 PMC 最耗人的三件事：料齐没齐、这周先做谁、急单会撞谁；规则方案 + 人工确认。外协深、抢楦狠须等外发单与模具档案达标再加深——按数据成熟度分阶段，不是功能残缺。

### 10.3 架构：为何能落地、卡点在哪

**已具备的落地骨架（勿推倒重来）：**

```text
schedule_engine（确定性提案，可审计）
        ↑ tools only
schedule_agent（可选，非关键路径）
        ↓ adopt
ScheduleDraft → confirm → OrderProcess 日期 / assignment
        ↑ 齐套闸门
material_service（池承诺 / ETA / kit_ready）
```

| 架构要点 | 现状 | 落地含义 |
|----------|------|----------|
| 单一写入口 | 确认才改计划 | 避免 AI/排产双写 |
| 运算与展示分离 | proposals / load API 已有 | 周视图多为前端/聚合 |
| 与齐套同账本 | 本系统即账本 | 不必外挂中台只读同步 |
| Agent 可关 | 工具白名单 | 一期验收不绑模型可用性 |
| 资源模型 | `工序 × 日` 产能 | 快、可测、可解释；细资源勿硬塞 v1 |

**架构侧已登记风险：**

| ID | 问题 | 后果 | 处置 |
|----|------|------|------|
| AR-1 | 齐套日未硬约束进计划窗口 / confirm | 能演示、现场一停线就否定模块 | **P0-1 必须合并前过线**（引擎 + 测试） |
| AR-2 | 被逼在 v1 塞成型线/模具时段占用 | 两套资源模型纠缠、返工 | 粗模型坚持；细资源另开域，B3a 后另议 |
| AR-3 | 无 B2a 实体却做外协分流接口 | 假能力、二次改造 | 先领域单据，再挂倒排 |
| AR-4 | 预计算缓存无输入哈希/版本失效 | 脏方案被快速采纳 | P1-备选：缓存可加载，**禁止**自动 confirm |
| AR-5 | 脏主数据下「正确算出错误计划」 | 信任崩盘 | 演示模式 vs 投产 confirm 权限开关 |
| AR-6 | 把精 APS（甘特/自动全表重排）拉进本期 | 状态空间爆炸、实施运维爆 | 砍；与路线图 P∞ / TODO 一致 |

**与「不能落地」路径对比（备案，用于挡范围）：**

| | 本整合路径（可落地） | 全文精 APS（不建议） |
|--|---------------------|---------------------|
| 状态空间 | 工单 × 工序 × 日 | 机台/班组/模具 × 小时 |
| 主数据 | BOM + 库存 + 粗产能 | + 线、模、换模、外协日历 |
| 失败模式 | 方案偏乐观 → 人改 | 约束过多无解 / 人工拆约束 |
| 与现网 | 增量 | 近似重做排程核 |

### 10.6 结论落款

- **需求侧：** 对主战场「大部分」**够用**；对有外协/楦模深痛的子集，须分阶段，诚实降预期。
