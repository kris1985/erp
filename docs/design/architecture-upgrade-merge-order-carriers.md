## 0. 一句话结论

现网是「销售行先落生产单 → 对生产单排产 → 合批不合单 → 货上主码=捆」的全链路 ERP。  
升级目标改为：**销售色码可产池 → 有比例的规格合单执行 → 父卡隐形串联 → 捆码个人 / 筐卡班组分阶段扫 → 完工入库或直发**；工艺主数据改为**部件并行 + 整鞋汇合**。

**不整体替换库表**；按阶段挂到现有 `SalesOrder*` / `Order` / `TraceUnit` / `MergeBatch` / `WorkLog` / `Shipment` / `Packing*` 上演进。

## 1. 现网 vs 目标（摘要）

| 域 | 现网 | 目标 | 裁决 |
|----|------|------|------|
| 销售 | `SalesOrder`→`Line`→`LineItem` | 同构；`LineItem`≈需求色码 | **保留** |
| 排产输入 | 已建好的 `orders`（生产单） | **可产色码需求**（order_size 语义） | **升级** |
| 生产原子 | 一销售行 → 一张生产单（多色码明细） | **款+色+码规格执行单**（可挂多销售色码） | **升级（有分配合单）** |
| 合批 | `MergeBatch` 纸面组批，账本仍分单 | 合批可作过渡；**终态=合单** | **终态改合单** |
| 工艺 | 产品级扁平 `OwnProductLabor` | 部件泳道并行 + 整鞋单线 + 齐套闸门 | **升级** |
| 货上码 | B2h：唯一主码=`TraceUnit` 捆 | **分阶段双主码**：合帮前捆 / 合帮后筐 | **修订 B2h** |
| 父流转卡 | 无 | 批次×色码后台头，**不打印不扫** | **新增** |
| 筐卡 | 无（合批卡不可报工） | 贴筐二维码=现场口中的「流转卡」 | **新增** |
| 报工 | 统一 `WorkLog` + `group_detail` | 仍统一 WorkLog；捆个人 / 筐班组；拆分明细实体化 | **加强** |
| 派工 | 工序可派整工序/色码/捆 | **分段**：成型包装到线(组)；针车捆到人 | **升级** |
| 完工 | 无成品仓；出货认可发量 | 筐完工：**入库 / 直发**；直发虚拟入→出 | **新增** |
| 箱唛 | `PackingPlan` 挂生产单 | 装箱挂**出货单**；边装边打 / 批量 / 补打 | **对齐并迁移维度** |
| 产线 | 无（TODO：有需求再做） | 可选主数据；班组/筐卡/负荷可挂线 | **P3+ 可选** |
| 多租户/采购/财务 | 已有 | 保持；合单不得糊应收与齐套池 | **不可回退** |

外部草案整库替换：**拒绝**。只吸收车间执行层 + 合单分配层。

## 2. 产品拍板（本轮锁定）

### 2.1 合单优于合批（执行层）

- **认同**：同款同色同码跨销售需求，物理上应合成一张**规格执行单**，再按比例回写销售色码。  
- **合单范围**：执行与现场载体（开裁、流转、报工、产量回写、出货拆分）。  
- **不合糊**：客户交期承诺、齐套占用、应收核销仍能追到销售色码/销售单；禁止无分配硬合并。  
- **现网「合批不合单」**：视为过渡风控，不是终态；与路线图 B3c「真合单」同向，本纲要将其提前为架构目标并拆阶段落地。

### 2.2 排产输入

- 排产池主数据从「整张生产单」升级为**可产销售色码行**（语义=草案 `order_size`）。  
- 排产/合刀产出：**规格执行单**（款+色+码）+ **分配行**（sales_line_item_id / qty / ratio）。  
- 过渡期：池可仍展示生产单，但内部算法与合单以色码需求为准。

### 2.3 载体三层（现场只认两码）

| 概念 | 物理 | 打印 | 谁扫 | 职责 |
|------|------|------|------|------|
| 父流转卡 | 无 | ❌ | 无人 | 合刀批次×色码；订单拆分比例；筐/捆追溯总入口 |
| 筐卡 | 贴筐 | ✅ | 组长/质检/仓管 | 现场「流转卡」；收料进度、合帮及后段班组报工、入库/直发 |
| 扎捆码 | 贴部件捆 | ✅ | 针车工人 | 合帮前个人计件 |

**话术定稿：** 工人口中的流转卡 = 筐卡；父卡仅系统使用。

**扫码权限状态机（修订 B2h）：**

```text
合帮前：个人计件只扫扎捆；组长扫筐可**自动/显式收料**、分活、看进度（筐卡不计个人产量）
合帮点：齐套校验通过 → 合帮报工（扫筐）
合帮后：成型/包装/入库只扫筐；捆码只读追溯，禁止后道报工
```

### 2.4 报工

- **借鉴**：个人（扎捆）、班组（筐卡）、班组个人拆分。  
- **落库**：继续以 `WorkLog` 为账本；增加载体类型（bundle/basket）；`group_detail` **升级为明细表**（人、双数、工价、工资、是否手调）。  
- **不做**：平行三套 `report_personal/team/team_detail` 业务表（除非迁移成本更低时再议）。

### 2.5 完工：入库 / 直发

- 包装末道完成后，扫筐卡弹出：**入库** | **直发**（受 `allow_direct_ship` 控制）。  
- **入库**：成品入库单 + 库存增加 + 筐卡「已入库」；后续出货从库存分配。  
- **直发**：后台虚拟入库并立即出库（净库存不变、流水完整）+ 按分配生成/关联出货 + 筐卡「已出货」。  
- **前置**：直发前**预装箱**明细必须已存在且数量勾平（挂筐/执行单；见 §11.2）；禁止「先直发再空装箱」。  
- **多销售色码一筐**：按父卡比例拆出货（或多销售行），界面不得只显示单一来源单号糊过去。

### 2.6 箱唛

- 数据源于装箱单；**预装箱**在包装段按筐产生后即可打草稿唛，正式唛在出货落成后打（见 §11.2）。  
- 入口：装箱「保存并打印」（主）、出货详情逐箱/批量、补打、可选极简打印页。  
- 直发确认可带「打印箱唛」，前提是**预装箱已齐**。  
- 最终装箱维度在**出货单**；预装箱阶段挂筐/执行单，直发或出货确认时过户落成。

### 2.7 工艺路线配置页

- **认同**「款式全流程：部件并行泳道 → 齐套交汇 → 整鞋单线」配置页。  
- 工价在路线行；头部分部件工价 / 整鞋工价 / 全鞋总价。  
- **齐套闸门权威**：挂在整鞋段勾选了「部件齐套检查点」的工序（通常=合帮）；红点交汇为展示，不另套规则。  
- 路线行需带报工模式（个人/组），与捆/筐扫码一致。  
- 裁断：若合刀批次一次执行，避免与每部件泳道「裁断」双重记账（开裁属批次动作或单独节点——实现时二选一写死）。

### 2.8 产线（可选，不阻塞合单/载体）

- **定位**：多成型线/多包装线时的负荷与派工维度；**默认关闭**。  
- **配置**：租户参数 `use_production_line`（对齐外部草案）；`false` 时全流程不展示产线字段。  
- **主数据**：`production_line`（车间、日产能双数、启用）；班组可挂 `line_id`（可空）。  
- **执行挂载（仅开关打开时）**：规格执行单可派线；筐卡记录 `current_line_id`；班组报工可带产线（便于负荷统计）。  
- **不做**：把产线当成账本主体；按产线领料/出货；无开关时强制选线。  
- **排期**：**P3+**（P0–P3 合单与载体不依赖产线）。

### 2.9 三段车间派工差异

> **一句话：** 成型/包装派到产线（组），执行单确认即完成；针车派到个人，组长扫筐分捆时顺手做。

| 车间 | 派工方式 | 何时完成 | 系统动作 |
|------|----------|----------|----------|
| 成型 / 包装 | **不显式派到人**；执行单挂产线（或班组）= 到组 | 生管确认执行单/派线时 | 后段扫筐班组报工；组内流水节拍不建模 |
| 针车 | **必须派到人**：扎捆码 ↔ 工人 | 组长扫筐收料/分活时 | 工人待做列表；报工校验「是否派给你」；组长看每人进度 |
| 裁断 | **单独定**（不与针车同一套每捆必派） | 开裁/合刀时 | 批次或到组即可；避免与部件泳道双重派工 |

**针车最简交互：** 组长平板扫筐卡 →（自动）收料 → 见部件捆清单 + 组员 → 拖拽/勾选分活 → 工人自扫或组长代报。收料不另造码；强制先收可配。

**派工本质（针车）：** 把扎捆码和人绑定。复用现网 `OrderProcessAssignment.trace_unit_id`（按捆派），不平行造第二套派工域；合单后挂规格执行单工序即可。

**收料认领（针车接筐）：**

- **默认：** 对该筐首次打开分活看板 / 分活 / 代报时**自动记收料**（时间+人，幂等）。  
- **可选：** 显式「确认收料」。  
- **严管开关：** `require_basket_receive_before_stitch`（默认关）。  
- **不做：** 收料专用码；裁断↔针车双人扫握手。

**未派是否可报（针车）：**

- **默认推荐：** 未派不可报（工人自扫须已派工）。  
- **组长代报（默认开）：** `stitch_leader_proxy_report=true` → 合帮前组长扫捆并指定工人，工资记该工人。  
- **降级开关：** `allow_unassigned_bundle_report=true` → 谁扫算谁（流程最短；不防冒领）——允许但不推荐作默认。

**其它约束：**

- 产线未开（P3+ 前）：成型/包装退化挂**默认班组**，语义仍是「到组、不派个人」。  
- 已报工/已开工的捆改派：硬拦或留痕。  
- 成型偶发个人计件：租户例外，不把成型做成全员捆派。

**排期：** P0-5（载体与扫码之后）；与 P1 合单并行可先落在旧生产单+捆上。

## 3. 目标领域模型（逻辑）

```text
SalesOrder
  └─ SalesOrderLine (款)
       └─ SalesOrderLineItem          「需求色码 / order_size 语义」
              │
              │  allocation (qty, ratio)
              ▼
     SpecExecutionOrder               「规格执行单：款+色+码」
       ├─ allocations[]               「多销售色码来源」
       ├─ MergeCutBatch?              「合刀批次（可一规格多筐）」
       │     └─ FlowParent (隐形)     「父流转卡：比例 + 追溯根」
       │           └─ BasketCard[]    「筐卡 = 流转卡」
       │                 └─ BundleTag[] 「扎捆，属筐」
       └─ WorkLogs / 完工入库|直发 / 出货拆分

OwnProduct
  ├─ parts[] + part_routes[]          「阶段1 并行」
  └─ style_route[]                    「阶段2 单线；含齐套检查点」
```

### 3.1 与现表映射（落地时优先演进）

| 逻辑对象 | 优先演进自 | 说明 |
|----------|------------|------|
| 需求色码 | `sales_order_line_items` | 增加可产/已分配数量字段 |
| 规格执行单 | 新表或演化 `orders` | **破「一行销售→一单」**；需迁移策略 |
| 分配行 | 新表 `execution_allocations` | 替代草案 `production_order_detail` |
| 合刀批次 | 演化 `merge_batches` | 升到规格+比例；不再只是纸面 |
| 父流转卡 | 新表或批次头字段 | 无码 |
| 筐卡 | `trace_units` 扩 `unit_type=basket` 或新表 | 可扫 |
| 扎捆 | 现有 `trace_units` bundle | 增加 `basket_id` / parent |
| 报工 | `work_logs` | 载体 FK + 组拆分表 |
| 成品库存 | **新** | 现网几乎无 FG；入库模式依赖 |
| 出货/装箱 | `shipments` + 装箱改挂出货 | 直发写流水 |
| 产线 | **新**（P3+） | 可选；`teams` / 筐卡 / 执行单可空挂 `line_id` |

## 4. 关键流程

### 4.1 从需求到合单执行

```text
销售确认
  → 色码需求进入可产池（齐套/交期过滤）
  → PMC 勾选同款同色同码多来源 → 生成规格执行单 + 分配比例
  → （可选）合刀批次 / 父卡
  → 开裁：生成筐卡 + 按部件扎捆并打印
```

### 4.2 现场报工与派工

```text
（成型/包装）执行单确认挂产线或班组 → 后段无需逐人派工
（针车）组长扫筐 → 分捆到人 → 工人待做列表
工人扫扎捆 → 校验派工归属 → 个人报工（工价取部件路线行）
组长扫筐   → 部件进度 / 齐套 / 合帮及后段班组报工（工价取整鞋路线行）
班组报工   → 写组报工头 + 个人拆分明细（可手调）
```

### 4.3 完工与出货

```text
包装段：按筐预装箱（挂筐/执行单）
包装末道完成 → 扫筐 → 入库 | 直发
  入库：FG 入账 → 日后出货时预装箱落成出货装箱 → 箱唛
  直发：校验预装箱合计 → 出货单+装箱落成 → 虚拟入出 → 可打箱唛
```

## 7. 明确不做 / 禁止

- 无分配表的硬合单、批次出货却不分来源。  
- 父流转卡打印或要求工人扫父卡。  
- 合帮后继续用扎捆码报成型/包装。  
- 筐卡与扎捆双计同一产量。  
- 直发时现造空装箱单再补录。  
- 用合单糊掉多租户、采购齐套池、应收应付已有口径。  
- 整库按外部 PostgreSQL 草案重建。  
- **无开关强制产线**；产线不得替代执行单/销售色码成为账本主体。  
- 成型/包装强制逐人派工（除非租户例外个人计件）。  
- 平行第二套派工表（应复用按捆 `OrderProcessAssignment` 语义）。  
- 智能排产**静默落库**改已确认队列。  
- 计件报工瞬间按 ratio **改写个人工资到销售单**。  
- 质检策略写成「全局绝不追个人」（针车有派工时除外）。  
- 已开工**无版本无新单**直接改尺码或增产。

## 8. 开放问题（实现前再拍一次）

1. 规格执行单：新表 vs 演化 `orders`（推荐新表 + 旧单适配期，避免大爆炸）。  
2. 成品仓粒度：仅按执行单色码数量，是否要库位（P2 可先无库位）。  
3. 裁断报工：批次级 vs 部件级（与工艺页裁断行去重）；**裁断派工到组还是到人**。  
4. 一筐是否允许混码（默认否；提案一筐一码）。  
5. 齐套闸门默认松/严（租户配置）。  
6. 产线日产能：仅配置值，还是后续用报工校准（P3+ 先配置即可）。  
7. 针车改派：已开工是否允许组长强改（推荐留痕允许 / 已报工禁止）。  
8. 完整前置工序图是否进 P0，还是长期只靠齐套检查点。  
9. 「同材质」合单分组：材质主数据从料号哪些字段取。

## 11. 生命周期闭环检查

> **裁决：** 车间**执行主链**在设计层可闭环；**全厂经营闭环**依赖现网采购齐套/应收/月结接驳。下列断环未补前，不得宣称「全生命周期已闭环」。

### 11.1 主链（应闭环）

```text
主数据(款/BOM/部件·整鞋路线/人·班组[/产线])
        ↓
接单 SalesOrder → 色码行
        ↓ 齐套过滤（现网料池 ← 须接 P1-6）
可产池 → 合单 → 规格执行单 + ratio
        ↓ 派线/组（成型）
开裁 → 父卡(隐) → 筐卡 + 扎捆
        ↓ 针车派捆→人
报工(捆个人 / 筐班组+拆分) → 计件工资账 →（现网）月结
        ↓ 合帮齐套闸门
成型/包装扫筐 → 质检/返修(支线，见 11.3)
        ↓
完工：入库 → FG → 出货(认销售) → 箱唛 →（现网）应收
     或直发 → 虚拟入出 + 出货(认销售) → 箱唛 ──↗
        ↓
销售色码：在制预估 → 入库后精确；执行单生命周期结束
```

| 环 | 状态 | 说明 |
|----|------|------|
| 需求→执行→回写销售 | ✅ 设计闭环 | ratio 贯穿合单、进度、入库、出货 |
| 载体父→筐→捆→合帮后只筐 | ✅ | §2.3 状态机 |
| 报工→计件工资 | ✅ | 认人×执行/报工 |
| 完工→出货→销售兑现 | ✅ | 入库/直发双路径 |
| 出货→应收/回款 | ✅ 靠现网 | 纲要不重画财务 |
| 接单→齐套→可产 | ⚠️ 半环 | **P1-6**：齐套/领料主体迁执行单 |
| 计件→订单成本 | ⚠️ 半环 | **P2-5**：入库按 ratio 归集落点 |
| 质检→返修→回筐 | ⚠️ 半环 | **P0-7 + P3-6** 数量勾平 |
| 变更/急单/补单回滚 | ⚠️ 半环 | **P3-5 + P3-6** |
| 采购→IQC→发料 | ◯ 纲要外 | 现网能力；经 P1-6 接执行单 |
| 应付 | ◯ 纲要外 | 保持现网 |

### 11.2 装箱与出货时序（原断环 → 定稿）

**问题：** 箱唛/装箱挂「出货单」，但直发时出货单才生成，易变成「先直发再空装箱」。

**定稿（P2-4）：**

```text
包装段：按筐预装箱（明细挂 basket / 执行单，可打草稿唛）
    ↓
完工确认
    ├─ 入库：FG 入账；日后建出货单时，预装箱过户/生成为出货装箱 → 打正式箱唛
    └─ 直发：校验预装箱合计=完工双数 → 生成出货单并落成装箱 → 虚拟入出 → 可打箱唛
```

禁止：直发确认瞬间无预装箱数据却「自动生成空装箱单」。

### 11.3 断环清单与补丁

| ID | 断环 | 补丁 Epic | 不补的后果 |
|----|------|-----------|------------|
| G1 | 合单后齐套/领料仍认旧生产单 | **P1-6** | 可产池与车间执行拧巴；争料乱 |
| G2 | 装箱挂出货 vs 直发才有出货单 | **P2-4** | 直发不能打唛或数量虚挂 |
| G3 | 减产/停产/作废无回滚可产与料占用 | **P3-6** | 池占死、料不释放 |
| G4 | 返修/次品与可入库数未勾平 | **P0-7 + P3-6** | 产量与工资/库存不平 |
| G5 | 人工成本归集无落账点 | **P2-5** | 毛利/接单面与计件对不上 |
| G6 | 裁断报工与部件泳道裁断双计 | §2.7 开放题 / 实现拍板 | 工价重复 |

### 11.4 边界（什么叫「闭环」）

| 宣称 | 条件 |
|------|------|
| **执行生命周期闭环** | 主链 ✅ + G1/G2/G3/G4 补齐 |
| **经营生命周期闭环** | 上式 + G5 + 现网采购/应收/月结回归验收通过 |
| **本纲要单独不承诺** | 重做总账、应付深度、多工厂 APS |

### 11.5 闭环验收（加测）

- [ ] 两张销售同色码合单 → 开裁多筐 → 报工 → 入库拆分后销售色码产量精确且合计勾平。  
- [ ] 同路径直发：预装箱 → 一键直发 → 出货+箱唛+应收；FG 净增为 0，流水有入有出。  
- [ ] 执行单占用料后停产：可产池与共享池占用释放正确。  
- [ ] 针车不良冻结返修回归后，合帮/入库可用数正确。  
- [ ] 计件月结与销售色码入库人工成本可对账（允许分时机，不允许无线索）。
