# 鞋厂余额制往来与周期对账

## 结论

客户和供应商往来采用双层模型：

1. 出货应收、采购到货应付、外协收回应付继续保留原始业务明细。
2. 收款和付款默认记入往来单位总账户，可选关联周期对账单，不要求指定原始单据。
3. 只有对方明确给出分单清单时，才登记逐单核销。

因此系统中的真实余额为：

```text
客户余额 = 全部有效应收 + 调整 - 全部已入账回款
供应商余额 = 全部有效应付 + 调整 - 全部已入账付款
```

原始应收/应付的 `received_amount`、`paid_amount` 只表示明确的逐单分配，不再代表往来单位真实余额。

## 结算政策

`partner_settlement_policies` 按往来单位和方向分别配置，支持：

- `balance_forward`：余额结转制。
- `open_item`：逐单核销制。
- `mixed`：对账单为主、逐单核销为辅。
- 逐笔、月结、半月结、旬结。
- 截账日、账期天数、若干月后的固定收付款日。

旧档案中的 `partners.payment_term_days` 继续作为无显式政策时的兼容值。

## 周期对账单

`account_statements` 保存某一期间的冻结快照：

```text
期末余额 = 期初余额 + 本期发生 + 本期调整 - 本期收付款
```

`account_statement_lines` 保存该快照的来源：应收、应付、调整、回款、付款和期初结转。

对账单生命周期：

```text
草稿 → 已确认 → 部分收付 → 已结清
           ↘ 有争议
草稿/未收付单据 → 已作废
```

收付款可直接关联已确认对账单。例如对账55万元、收到30万元：

```text
对账金额 550,000
已收金额 300,000
剩余金额 250,000
状态     部分收款
```

不产生任何虚假的出货单核销关系。

## 未分单收付款

收付款输出包含：

- `allocation_mode=account`：只记往来余额。
- `allocation_mode=statement`：关联对账单。
- `allocation_mode=document`：对方明确指定原始单据。
- `allocated_amount`：明确逐单分配金额。
- `unallocated_amount`：既未关联对账单、也未逐单分配的金额。

未分单金额仍然立即减少客户/供应商真实余额。系统做账龄分析时按最早发生或最早到期顺序推算，但必须标识为系统推算，不能当成对方指定。

## 利润口径

回款和付款不直接改变订单毛利：

```text
估算毛利 = 已出货收入 - 材料成本 - 人工成本 - 其他成本
```

退货、品质扣款、价格折让、客诉赔偿等经双方确认后，应形成正式调整，冲减应收和净销售收入；供应商价格补差、退货和品质扣款相应调整应付和材料/加工成本。

## 兼容策略

- 保留现有应收、应付和逐单核销表，不删除历史数据。
- 收付款的逐单分配数组改为可选，合计允许小于收付款金额，但不得超过。
- 现有已分配数据仍可正常作废和反核销。
- 客户/供应商汇总与经营 KPI 改用账户借贷余额。
- 明细页面继续展示来源和明确逐单核销，汇总页面展示真实往来余额。
