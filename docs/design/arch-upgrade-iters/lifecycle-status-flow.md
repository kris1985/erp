# 销售单 · 销售明细 · 生产执行单 — 生命周期状态流转

> **状态：** 📝 定稿（正确态，不迁就现网字段名）  
> **适用范围：** 架构升级目标态（有分配合单 + 色码需求池）  
> **总纲：** [`../architecture-upgrade-merge-order-carriers.md`](../architecture-upgrade-merge-order-carriers.md)  
> **原则：** 状态由**业务事件自动推进**为主，手工仅作纠错/关闭；销售认客户承诺，执行认车间事实。

---

## 0. 对象分层（先分清谁有状态）

> **方案 C：** 对外主卡片是**执行单头**（一款一头、可多码）；码明细可挂多条销售色码（合单 ratio）。下文「执行单状态」默认指**头**的汇总态；码明细可有自己的计划/完工量。

```text
SalesOrder                 销售单头 —— 对客户的一纸合同/订单
  └─ SalesOrderLine        销售明细（款，可带主色/交期/单价）
       └─ SalesLineItem    销售色码行（色+码+双数）← 可产/分配/进度原子
              │ allocation（排产确认时写入）
              ▼
       ExecutionHeader     执行单头（人见 XE-…）—— 齐套汇总 / 锁料 / 开裁入口
            └─ SpecExecution 码明细（可多销售来源）
```

| 对象 | 状态回答的问题 |
|------|----------------|
| **销售单头** | 这张客户单整体走到哪了？ |
| **销售明细（款行）** | 这一款行是否已排、在产、交清？ |
| **销售色码行** | 这一色码还剩多少可产/在产/已产/已出？ |
| **执行单头** | 车间这张活是否已排、开裁、在做、做完？ |

色码行以**数量字段**为主状态（比枚举更准）；头/款行/执行单头用枚举汇总。

**料与状态正交（勿写进状态码）：**

| 阶段 | 缺料/采购 | 锁库存 |
|------|-----------|--------|
| 确认接单后、未排产 | **需求缺料**绑销售单/色码；可下长周期采购 | **不锁** |
| 执行单已落库 | **生产缺料**绑执行单头 | **可锁**到执行单头 |
| 与订单无关的钉子/锤子等 | **备库采购**绑物料/安全库存 | 不走执行单锁料 |

## 1. 总览流转（主路径）

```text
销售草稿 → 确认接单
    → 色码进入「待排产 / 可产需求」（不要求齐套；齐套仅作可选过滤）
    →（并行）需求缺料 → 长周期采购 → 到料入共享池
    → 合单/排产确认 → 生成执行单（已排产 planned）
    →（开裁前）生产缺料查看；HITL 锁料
    → 首道齐套硬闸通过 → 开裁生筐捆（已开裁 cut）
    → 收料/首报工（生产中 in_progress）
    → 合帮…包装 → 完工入库或直发（执行完成）
    → 出货（销售色码已出累加）
    → 行/头交清或关闭（销售完成）
```

**软/硬闸：** 缺料可软排进计划；**开裁**才卡首道齐套。禁止「必须齐套才能进待排」。

异常支线：取消、停产、减产、返修（不改变主链对象，只改数量与执行单状态）。

## 2. 销售单头 `SalesOrder.status`

| 状态码 | 名称 | 含义 | 进入条件（自动优先） | 可手工 |
|--------|------|------|----------------------|--------|
| `draft` | 草稿 | 未对客户生效 | 创建 | — |
| `confirmed` | 已确认 | 已接单，可进入可产/排产 | 确认接单 HITL | 驳回回草稿视策略 |
| `in_fulfillment` | 履约中 | 至少一色码已分配执行或已出货 | 首张执行单确认 **或** 首笔出货 | 一般不必手点 |
| `completed` | 已完成 | 所有未取消明细已交清（或差额关单） | 全部有效色码 `shipped_qty >= qty`（或关单） | 差额关单需权限 |
| `cancelled` | 已取消 | 整单作废 | 无在产/无出货时取消 | 是 |

```text
draft ──确认──► confirmed ──首执行或首出货──► in_fulfillment ──交清/关单──► completed
   │                │                              │
   └──── 删除/作废 ─┴──────── 取消 ─────────────────┴──► cancelled
```

**不做：** 头上单独「生产中」与执行单抢语义；履约中已覆盖「在产或在交」。

## 3. 销售明细（款行）`SalesOrderLine.status`

| 状态码 | 名称 | 含义 | 进入条件 |
|--------|------|------|----------|
| `pending` | 待排产 | 确认后尚未分配执行 | 随头确认 |
| `partial_scheduled` | 部分排产 | 部分色码/数量已进执行单 | 有分配且未满 |
| `scheduled` | 已排产 | 计划量已全部分配（可尚未开工） | 分配合计 ≥ 行需求 |
| `in_production` | 生产中 | 下属执行单至少一张 `in_progress`+ | 自动 |
| `partial_shipped` | 部分出货 | 已出货但未交清 | 自动 |
| `completed` | 已完成 | 本行交清或关行 | 自动/关行 |
| `cancelled` | 已取消 | 本行作废 | 手工（无在产约束） |

可简化实现为更少枚举，用数量推导展示态（**与色码 §4 同一优先级**）：

```text
若 cancelled → 已取消
否则若 shipped >= qty → 已完成
否则若 shipped > 0 → 部分出货
否则若 produced > 0 且 shipped < qty → 仍用部分出货或「已产未出清」展示（有出货用部分出货）
否则若任意关联执行 status ∈ {cut, in_progress, suspended} 或 wip > 0 → 生产中
否则若 allocated >= qty → 已排产          ← 含仅 planned、尚未开裁
否则若 allocated > 0 → 部分排产
否则 → 待排产                               ← 头已确认且尚未排产确认
```

**推荐：** 库内可存粗状态，**列表展示优先用数量推导**，避免手工点「已排产」与分配表不一致。

**注意：** 仅有 `planned` 执行单 ≠ 生产中；跟单应看到「已排产」，PMC 去执行单开裁。

## 4. 销售色码行（数量真相，弱枚举）

不强制独立 status 枚举；核心字段：

| 字段 | 含义 |
|------|------|
| `qty` | 客户需求双数 |
| `allocated_qty` | 已分配到执行单的双数 |
| `wip_qty` | 在制预估（执行未入库，按 ratio 汇总） |
| `produced_qty` | 已入库/直发确认的精确产量 |
| `shipped_qty` | 已出货双数 |

**推导展示（优先级与 §3 对齐）：**

| 展示 | 条件 |
|------|------|
| 待排产 | `allocated_qty = 0`（头已确认） |
| 部分排产 | `0 < allocated < qty`，且尚无 cut/在制/已产主导 |
| 已排产 | `allocated >= qty`，关联执行至多 `planned`，`produced=0` 且无 wip |
| 生产中 | `wip > 0` **或** 关联执行 ∈ `{cut, in_progress, suspended}` |
| 已入库未出清 | `produced > 0` 且 `shipped < qty` |
| 已交清 | `shipped >= qty` |

**不要：** 「有关联执行未完成」把 `planned` 算成生产中（会与已排产打架）。

事件更新：

- 确认接单 → 色码进入待排需求（allocated 仍为 0）；可算**需求缺料**  
- 排产确认 → `allocated_qty +=`；生成/更新执行单  
- 报工/在制 → 更新 `wip` 预估  
- 入库/直发 → `produced_qty +=`（精确），下调 wip  
- 出货 → `shipped_qty +=`  
- 停产释放 → `allocated` 回退可产池；锁料占用释放

## 5. 生产执行单头 `ExecutionHeader.status`（车间真相）

> 码明细可跟头同步或保留计划/完工量；**对外状态机以头为准**（方案 C）。

| 状态码 | 名称 | 含义 | 进入条件 | 自动/手 |
|--------|------|------|----------|---------|
| `planned` | 已排产 | 已确认执行、未开裁 | **排产/合单确认**落库（不是确认接单） | 自动（确认动作） |
| `cut` | 已开裁 | 已生成筐/捆 | 开裁 API 成功（建议卡首道齐套） | **自动** |
| `in_progress` | 生产中 | 车间已实际开工 | **首笔有效报工**（推荐）；可选：收料也触发 | **自动** |
| `completed` | 已完成 | 计划量已入库或直发结清（或完工关闭） | 完工入库/直发勾平；或末道完成策略 | **自动** |
| `suspended` | 已停产 | 暂停，可恢复或关 | 停产操作 | 手工 |
| `cancelled` | 已取消 | 作废，释放分配与占用 | 未开工或已回滚后取消 | 手工 |

```text
planned ──开裁──► cut ──首报工(或收料)──► in_progress ──完工入库/直发──► completed
   │               │                         │
   └── 取消 ───────┴── 停产 ──► suspended ────┘ 恢复→ in_progress / cut
                              └── 关单回滚 → cancelled
```

**禁止：** 销售「确认接单」直接创建 `planned` 执行单（那是旧双轨）；正确态必须经排产/合单确认。

### 5.1 「生产中」怎么进（定稿）

| 触发 | 是否默认 | 说明 |
|------|----------|------|
| **首笔有效报工** | **是（主）** | 捆个人/筐班组/组长代报均算；与现网报工推进一致 |
| 针车收料 | 可选 | `execution_start_on_receive=true` 时，收料也把 `cut→in_progress` |
| 开裁 | 否（只到 `cut`） | 开裁≠工人已干；保留「已开裁」便于齐套后等针车 |
| 手动「改为生产中」 | 兜底 | 仅纠错；**禁止**作为开工唯一手段 |

**已开工（变更规则用）：** `status ∈ {cut, in_progress, completed, suspended}` **或** 已有报工记录 —— 已开裁即限制改码/增产更稳。

### 5.2 「已完成」怎么进

- 入库/直发累计 `finished_qty >= planned_qty`（允许配置尾差），或  
- 显式「完工关闭」（短码关单，权限）。  

完成后执行单不再报工（返修另挂任务）。

## 6. 对象间状态如何联动

```text
执行 planned     → 销售色码 allocated↑；款行/头 → 履约中（若尚 confirmed）
执行 cut         → 色码仍 allocated；展示可「已开裁」
执行 in_progress → 色码 wip↑；款行 in_production
执行 completed   → 色码 produced↑、wip↓；若未出货则待出货
出货确认         → 色码 shipped↑；款行 partial_shipped / completed
全部色码交清     → 头 completed
执行 cancelled   → allocated 回退；头/行按剩余推导
```

**禁止反向：** 不要靠点销售单「生产中」去驱动执行单；也不要销售「完成」自动灌执行完成。

---

## 7. 与出货/入库的衔接（执行完成之后）

| 路径 | 执行单 | 销售色码 |
|------|--------|----------|
| 入库 | → `completed` | `produced↑`；随后出货 `shipped↑` |
| 直发 | → `completed` | `produced↑` 且 `shipped↑`（同时或紧随） |

执行单 **completed 不表示客户已收货**，只表示车间侧做完；客户侧完成看 `shipped`。

## 8. 进度展示（列表 / 详情必须有）

> **原则：** 进度用**双数 + 百分比 + 阶段条**展示，不靠手点状态冒充进度。合单在制用 ratio **预估**，入库/直发后用 **精确** produced。

### 8.1 四条进度轨（不要混成一根糊涂条）

| 轨 | 公式（色码行） | 含义 | 何时准确 |
|----|----------------|------|----------|
| **排产** | `allocated_qty / qty` | 需求里有多少已进执行单 | 分配确认即准 |
| **在制** | `wip_qty / qty` | 车间已干未入库的预估 | 报工按 ratio 估；入库后清零转已产 |
| **已产** | `produced_qty / qty` | 入库/直发确认产量 | 完工后准 |
| **已出** | `shipped_qty / qty` | 发给客户 | 出货确认后准 |

**展示纪律：**

- 对外客户/跟单默认强调：**已产 + 已出 / 需求**（完成数与发出数都要，缺一不可）。  
- PMC/车间默认强调：**已产+在制 / 已分配**，以及执行单工序进度。  
- 同一 UI 勿把「排产%」和「出货%」画成一条无图例进度条。

### 8.2 销售色码行（最细，真相）

```text
需求 100 | 已排 100 | 在制≈40 | 已产 50 | 已出 30
进度文案示例：出货 30% · 入库 50% · 在制约 40
```

| UI 元素 | 内容 |
|---------|------|
| 主数字 | `已出/需求` 或按角色切换「已产/需求」 |
| 次数字 | `已排` `在制≈`（预估加「约」） |
| 迷你条 | 建议堆叠或双条：已出 / 已产未出 / 在制 / 未产；悬停看绝对双数 |
| 标签 | 与 §4 推导态一致（待排产/生产中/部分出货…） |

合单时：在制预估 = Σ(执行单在制双数 × 该色码 ratio)；入库后 produced 按拆分精确写。

### 8.3 销售明细（款行）

对下属色码 **求和** 后同四轨：

```text
排产% = Σallocated / Σqty
在制% ≈ Σwip / Σqty
已产% = Σproduced / Σqty
已出% = Σshipped / Σqty
```

列表推荐一列「履约」：`已出/需求` + 小字 `产已产/需求`；点开下行看色码。

### 8.4 销售单头

对有效（未取消）明细汇总，同上四轨。  
头卡片可用：

```text
履约 120/200（60%）· 已产 150 · 在制约 20 · 排产 200/200
```

状态徽章用 §2（履约中/已完成），**百分比单独显示**，避免「状态=进度」。

### 8.5 生产执行单（车间）

| 层级 | 展示 |
|------|------|
| 整单 | `完工双数/计划双数`；状态徽章 planned/cut/in_progress/completed |
| 工序 | 每道 `报工合格累计/本工序计划`（计划默认=执行 planned_qty） |
| 部件（合帮前） | 每部件：下属捆完成数/捆数，或合格双数/计划；齐套检查点前标红未齐 |
| 筐 | 筐计划、已报后道、收料时间；多筐时列表进度 |

**工序条（推荐）：** 横向步骤 planned → 当前高亮 → 已完成打勾；合帮节点单独标「齐套」。

执行单若挂多销售来源，详情显示分配表：

```text
SO-A 色码 60% · 预估在制/已产按比例拆（入库后显示精确拆分）
SO-B 色码 40% · …
```

### 8.6 阶段时间轴（详情页共用）

销售色码或执行单详情可展示事件轴（只读）：

```text
确认接单 →（可选）需求采购 → 排产确认 → 锁料 → 开裁 → 收料 → 首报工 → … → 合帮 → 入库/直发 → 出货
```

「齐套」不作为接单后的必经节点；可在时间轴上标「预计齐套日 / 首道齐套」为里程碑，未发生则灰显。  
每点：时间、操作者。用于跟单解释「卡在哪」，不替代数量进度。

### 8.7 API 建议（只读聚合）

```text
GET /sales-orders/{id}/progress
  → header: { qty, allocated, wip, produced, shipped, pct_* }
  → lines[]: 同上 + items[] 色码明细

GET /executions/{id}/progress
  → { planned, finished, status, processes[], parts[], baskets[], allocations[] }
```

`wip` 计算：执行未完成前，取关键工序合格数策略（I0/I1 可先用「末道已报或筐当前进度」简化，文档标「预估」）。

### 8.8 角色默认看什么

| 角色 | 默认主进度 | 次要 |
|------|------------|------|
| 跟单/老板 | 销售头/行 **已产 + 已出 / 需求** | 交期、已排 |
| PMC | 色码 **已排/需求** + 执行状态 | 齐套、在制、已产 |
| 车间主任 | 执行单 **工序/部件/筐** | 收料滞留 |
| 仓管 | **已产待出**（produced−shipped）、预装箱 | 直发 |

### 8.9 验收（进度）

- [ ] 色码行同时能读到 allocated/wip/produced/shipped，在制带「约」或预估标记  
- [ ] 合单两来源入库后 produced 拆分勾平，展示与分配表一致  
- [ ] 款行/头进度 = 下属色码求和，无手填百分比  
- [ ] 执行单有整单双数进度 + 工序条；有部件时合帮前可见部件齐套进度  
- [ ] 未入库不把 wip 写成「已产」  
- [ ] 销售订单管理宽表按 §8.10 改造后可走查  

### 8.10 销售订单管理宽表 · 列改造清单

> **现状：** 一张表里订单头（rowspan）+ 款行 + 码段矩阵 + 数量/单价/交期/备注 + 状态徽章（如待确认/待生产）+ 操作。  
> **原则：** **不拆表、不拆页**；进度嵌在款行；码段矩阵保持录入密度；执行单另入口下钻。

#### 列布局（保留 / 改 / 增）

| 列区 | 处置 | 说明 |
|------|------|------|
| 订单号 / 客户 / 下单日（头 rowspan） | **保留** | 头上可加汇总徽章：`履约中` / `已完成`（§2） |
| 序号 | 保留 | 款行序 |
| 款号 + 缩略图 | 保留 | 点击款号 → 详情；可增加「关联执行」入口 |
| 颜色 / 面料等 | 保留 | 款行属性 |
| **码段矩阵** | **保留录入** | 默认**不**把格子刷成进度色；悬停/点击格 → tooltip：`该码 需求/已排/已产/已出`（有数据才显） |
| 数量合计 | 保留 | 行需求双数 |
| 单价 / 金额 | 保留 | |
| 交期 / 备注 | 保留 | |
| **状态徽章** | **改** | 挂**款行**，文案改为数量推导（下表）；勿再手点「待生产」冒充排产 |
| **履约进度（新列）** | **增** | 宽约 120–160：**必须同时展示已产、已出**（见下）；小字补已排/约在制 |
| 操作 | 保留 | 编辑 / 加行 / 更多；更多中可加「查看执行单」 |

**合计行：** 现有数量/金额合计保留；右侧加整单 `已产合计`、`已出/总需求`。

#### 进度列怎么写（款行）

「已完成多少双」= **已产** `produced`（入库或直发确认），**要**，且跟单高频看。

| 优先级 | 展示 | 含义 |
|--------|------|------|
| **主行（必显）** | `已产 a / 需求 q` | 车间侧做完多少（入库/直发） |
| **主行（必显）** | `已出 b / 需求 q` | 发给客户多少 |
| 次行 | `已排 c`；若 wip>0 则 `约在制 w` | 排产与在制预估 |

推荐排版（单列两行）：

```text
产 50/100 · 出 30/100
排 100 · 约在制 20
```

或并排短标签：`产50` `出30` `/100`，避免只有出货没有完成数。

**不要：** 只显示已出而省略已产（仓有货未发时跟单会误判「没做完」）。  
**不要：** 用状态徽章「已完成」代替双数（徽章≠进度）。

#### 款行状态徽章文案映射（替换「待确认/待生产」混用）

| 推导条件（款行汇总） | 徽章文案 | 备注 |
|----------------------|----------|------|
| 销售头仍为草稿 / 未确认 | **待确认** | 仅头未确认时行上可同显或灰显 |
| 头已确认且 allocated=0 | **待排产** | 替代笼统「待生产」 |
| 0 < allocated < qty | **部分排产** | |
| allocated≥qty 且执行至多 planned、无在产/已产 | **已排产** | |
| wip>0 或关联执行 ∈ {cut, in_progress, suspended} | **生产中** | 不含仅 planned |
| shipped>0 且未交清 | **部分出货** | |
| shipped≥qty | **已完成** | |
| 行取消 | **已取消** | |

筛选 Tab 可与徽章对齐：待确认 / 待排产 / 生产中 / 部分出货 / 已完成（「待生产」逐步弃用或映射到待排产）。

#### 交互

| 动作 | 行为 |
|------|------|
| 点进度列 / 进度条 | 抽屉或下行展开：色码四轨明细 + 关联执行单列表（计划/状态/完工） |
| 点码段格 | 编辑数量（未排产约束按变更规则）；已排产后改量走变更策略 |
| 点款号 | 产品/行详情（现有） |
| 头订单号 | 订单详情；展示头级四轨汇总 |

#### 信息架构示意（单行）

```text
| 头 rowspan | # | 款号+图 | 色/料 | [码段...] | 数量 | 价 | 额 | 交期 | 备注 | 徽章 | 产50/100·出30/100 | 操作 |
|            |   |         |       |           |      |    |    |      |      | 生产中 | 排100 · 约在制20   |      |
```

#### 明确不做（本表）

- 把执行单工序条塞进销售宽表每一行  
- 码段每个格子默认显示四轨数字（过密）  
- 为进度再建第二张「进度专用表」当主入口

| 波次 | 内容 |

## 10. 和现网差异（对照，非本文件义务）

| 点 | 现网大致 | 本文正确态 |
|----|----------|------------|
| 确认接单后 | 常「确认生产」直接建执行单/桥接单 | **只入待排**；排产确认才建执行单 |
| 生产主体 | `orders` 一销售行一单 | 执行单头 + 码明细；可多销售色码 |
| 缺料/锁料 | 多挂生产单 | 需求缺料→SO；锁料→执行单头 |
| →生产中 | 报工自动（已有） | **保持**；增加 `cut`，可选收料开工 |
| 销售头状态 | 较粗 | `in_fulfillment` 覆盖在产在交 |
| 明细进度 | 弱 | 色码四轨数量 + 展示推导 |
| 进度条 | 常混阶段 | 排产/在制/已产/已出分轨 |

落地时可先映射：`confirmed≈confirmed`，`in_progress≈in_progress/in_fulfillment`，不必一次改名。

## 11. 验收要点

- [ ] **仅确认接单、未排产：无执行单**；色码/款行展示待排产；可算需求缺料  
- [ ] 排产确认后执行为 `planned`，销售 `allocated` 勾平；头可进 `in_fulfillment`  
- [ ] 仅 `planned` 时销售展示「已排产」而非「生产中」  
- [ ] 开裁只到 `cut`，不等于生产中（除非开收料开工开关）  
- [ ] 首报工后执行必为 `in_progress`，无需再手点  
- [ ] 入库/直发后执行 `completed`，销售 `produced` 勾平；出货后 `shipped` 勾平  
- [ ] 列表上「部分排产/生产中/部分出货」与分配/产量/出货数量一致，不靠手点枚举  
- [ ] §8.9 进度展示验收全部通过
