# 执行单（方案 C）：一款一头 · 码为明细

> **状态：** ✅ 产品拍板（2026-08-12）· 实施中  
> **总纲：** [`../architecture-upgrade-merge-order-carriers.md`](../architecture-upgrade-merge-order-carriers.md)  
> **背景：** 一码一张「执行单」对外单太多，缺料/锁料过碎；又不宜多码糊成一张不可拆账本。

---

## 1. 裁决

**选方案 C：执行单（头）+ 码明细（子执行）。**

| 层 | 人怎么叫 | 粒度 | 职责 |
|----|----------|------|------|
| **执行单**（头） | 菜单/列表主卡片 | 同订单产品行 · **同一产品** · 可含多码 | 确认生产结果、缺料汇总、锁库存、催采购 |
| **码明细** | 点进才看，可折叠 | **产品 + 尺码**（色随产品） | 合单（多客户同码）、开裁筐捆、报工进度、入库/出货回写 |

**对外不叫「任务」。** 「生产单」仅过渡桥接影子单，不当主业务单。

**不选 A**（纯一码一张对外暴露）— 单多、锁料碎。  
**不选 B**（一款一张不可拆多码账本）— 跨客户同码合单与码级出货易糊。

---

## 2. 操作路径（目标体验）

```text
订单「确认生产」
  → 每个产品行生成 1 个【执行单】
  → 执行单下按色码行挂多码明细（每码一条 SpecExecutionOrder）
  → 缺料 / 锁料：对执行单一头操作（内部按码展开 BOM）
  → 开裁：可对执行单下多码合刀，或按码开
  → 多客户同产品同码：在码明细层合单（分配 ratio）
```

侧栏 / 列表叫 **执行单**；点进看多码明细。  
「跨单合单」仅偶尔用。

---

## 3. 与现网对象映射

| 现有 / 新建 | 方案 C |
|-------------|--------|
| `execution_headers`（新建） | **执行单（头）**，人见单号 `XE-…` |
| `SpecExecutionOrder` + `header_id` | **码明细**；单号 `{头号}-{尺码}` |
| 桥接 `orders` | **一执行单一桥接单**（多码明细同挂） |
| 旧仅下生产单 | 「确认生产」改为建执行单头 + 码明细 + 一桥接单 |

---

## 4. 实施顺序

1. 模型：`execution_headers` + `SpecExecutionOrder.header_id` + 销售行挂头  
2. 确认生产 → 建执行单 + 多码明细（本单全做）  
3. 缺料汇总 / 锁料 API 与 UI 按 `header_id` 聚合  
4. 列表按执行单头；跨单合单仍打在码层  
5. 再迁齐套主体到执行单/码明细  

---

## 5. 非目标

- 不同产品合进同一执行单  
- 无分配硬合并多客户多码  
- 一上来删除所有桥接 PO
