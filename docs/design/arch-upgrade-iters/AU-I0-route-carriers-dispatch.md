## 0. 目标 / 非目标

**目标**

1. 产品可配「部件并行 + 整鞋单线」工艺，工价在路线行，齐套检查点可配。  
2. 现场两种可扫码：扎捆（人）、筐卡（流转卡）；父卡概念本迭代可不落独立表（开裁可后置到 I1）。  
3. 合帮前后扫码权限正确；针车捆派到人；成型/包装到组。  
4. 班组报工拆分明细化；技能系数可预填；质检责任分段 + 返修挂载体可演示。

**非目标**

- 规格执行单 / 分配 ratio / 可产色码池  
- 成品仓、直发、改出货挂载  
- 改排产池主键、产线主数据

### 2.1 合帮前谁可以报？（适配不同厂）

| 模式 | 谁扫什么 | 工资记谁 | 适用 | 配置 |
|------|----------|----------|------|------|
| **A 工人自扫（推荐）** | 工人扫**扎捆** | 扫码工人（须已派工） | 防冒领、看每人进度 | 默认主路径 |
| **B 组长代报** | 组长扫**扎捆**（或看板点捆）并指定工人提交 | **被指定工人**，不是组长 | 工人不持机/不愿扫 | `stitch_leader_proxy_report=true`（**默认开**） |
| **C 谁扫算谁** | 任意持捆人自扫 | 扫码人 | 最省事、弱管控 | `allow_unassigned_bundle_report=true`（默认关） |

**硬规则：** 合帮前计件载体只能是**扎捆**（组长代报也扫捆，禁止用筐记针车个人产量）。筐在合帮前只用于收料/分活/进度。合帮后只扫筐。

**一句话：**「合帮前个人只扫捆」约束的是载体，不是「禁止组长报」——**必须支持组长代报**，默认允许。

### 2.2 收料认领（扫筐，轻量）

裁断送筐到针车后，系统应有「已收料」事件（时间 + 操作人），用于交界对账、滞留、在制位置。

| 做法 | 说明 | 默认 |
|------|------|------|
| **自动收料（推荐）** | 对该筐首次打开分活看板 / 首次分活 / 首次代报时，自动写收料流水 | **开** |
| **显式收料** | 看板「确认收料」按钮，爱对账的厂用 | 可选入口常驻 |
| **强制先收再干** | 未收料不可分活/报工 | **关**（`require_basket_receive_before_stitch=false`） |

**不做：** 收料专用码；裁断↔针车双人扫握手。

**一句话：**收料值得做；做成扫筐自动带收料，不要多扫形式主义。

## 4. 走查脚本（验收）

| # | 步骤 | 期望 |
|---|------|------|
| 1 | 配置款：4 部件泳道 + 合帮检查点 + 成型包装 | 总工价=部件+整鞋 |
| 2 | 现网生产单开裁（或过渡 API）生成 1 筐 N 捆并打印 | 筐卡/捆标样式正确 |
| 3 | 组长扫筐 → 前帮派张三 → 张三扫前帮报工 | 成功；李四扫前帮失败；**首次分活自动产生收料流水** |
| 3a | 显式点「确认收料」 | 可重复点应幂等；已有收料不重复灌水 |
| 3b | 组长代报：扫前帮捆，指定张三提交 | 工资记张三；`operator`/`source` 可区分代报 |
| 3c | `stitch_leader_proxy_report=false` 时工人外账号代报 | 拦截 |
| 3d | `require_basket_receive_before_stitch=true` 且未收料就分活 | 拦截；收料后可分 |
| 4 | 未齐套点合帮 | 拦截 |
| 5 | 合帮后扫捆报成型 | 拦截；扫筐可报 |
| 6 | 组长扫筐班组报工 → 按系数预填 → 改一人数量提交 | 明细表有行；工资按改后数 |
| 7 | 针车不良登记（已派捆） | 责任人可带出；返修任务挂捆 |
