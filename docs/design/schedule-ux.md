# 排产默认体验：方案甘特 · 确认才下发

> **状态：** 📝 产品定稿（待排期落地）· 2026-08-13  
> **性质：** 排产**默认路径**的产品设计。先定人怎么排，再映射现网引擎与表。  
> **原则（决策顺序，不可颠倒）：**  
> 1. 极致用户体验是前提  
> 2. 符合鞋厂实际情况是基础  
> 3. 做正确的事始终不变  
> 4. 现有模型与竞品最后才看  
> **生命周期：** [`arch-upgrade-iters/lifecycle-status-flow.md`](./arch-upgrade-iters/lifecycle-status-flow.md)  
> **执行单粒度：** [`arch-upgrade-iters/AU-execution-task-C.md`](./arch-upgrade-iters/AU-execution-task-C.md)（一款一头、码为明细）  
> **引擎能力（实现手段，不是产品形态）：** [`aps-dev-review.md`](./aps-dev-review.md) · [`A2c-schedule-compare.md`](./A2c-schedule-compare.md) · [`schedule-params-sme-decision.md`](./schedule-params-sme-decision.md)

本文**收回**把「勾选款色落执行单」叫作排产、以及把智能方案藏在「改工序日」里的做法。AU-I3 的色码输入、合单落执行单、插单 HITL 仍然有效，但**下发时机与默认界面**以本文为准。

---

## 0. 一句话

排产页只有一条路：待排款色上图 → 三套方案在同一张生产甘特上切换 → 人拖改 → 确认后才生成执行单。智能排产不出现第二次；已排待开裁不是第二份列表。

---

## 1. 为什么要写这份

现网把同一件事拆成三摊，生管会糊涂：

| 现网入口 | 实际在干什么 | 问题 |
|----------|----------------|------|
| 选款下生产 · 确认排产 | 把勾选数量复制成执行单，工序日人看不见 | 确认的不是计划 |
| 改工序日 · 智能方案 | 真正的多方案 + 倒排草稿 | 往往执行单已经有了；智能排产藏在次要入口 |
| 已排待开裁 + 执行单页 | 同一批 `ExecutionHeader` | 两份列表、两套名字 |

正确的事没有变：确认的是**计划**（何时、何序、会不会爆），不是另一张数量表。未确认没有车间指令。缺料可软排，开裁再卡首道齐套。锁料不是排产按钮。

做错的是形态：两套草稿、两个「智能」、两份已排列表。

## 2. 目标 / 非目标

**目标**

1. 打开「生产 → 排产」即进入智能排产；第一眼是时间条，不是勾选表当首页。  
2. 默认给出可对比的 3 套方案（保交期 / 保现场 / 只排齐套），在**同一张甘特**上切换。  
3. 人直接改图（拖条、改开裁日）；改完仍是草稿。  
4. **确认方案**才下发：生成执行单（方案 C：同款同色一头、码为明细）并写入人看过的工序窗口。  
5. 执行单是排产确认的**产出**。侧栏「执行单」只做开裁/备料/报工/入库。  
6. 缺料、超产、逾期、争料画在条上，不另开报表当主路径。

**非目标**

- 机台 / 成型线 / 班次小时甘特（无线别主数据时做了会假；有档案后另文，见 AU-I3plus）  
- 无人自动重排并落库  
- 确认排产时自动锁库存、自动派工  
- 接单与排产并成一步  
- 必须齐套才能进入待排  
- 把合批纸面重新做成第二套账本

## 3. 鞋厂现实（设计约束，不是参数清单）

- PMC 通常 1～2 人，兼跟单；脑子里的工具是 Excel：行是款，列是天，颜色是裁/针/成/包。  
- 产能口头单位是「成型一天多少双」，不是机台开动率。  
- 料经常晚到，计划仍要先排上；开裁当天才真正要料。  
- 同款同色、两家客户，常常一起开裁。  
- 急单是口头插进来的；要看见挤谁，不能静默改已开裁的单。  
- 没有 APS 专员，常调旋钮很少；不信看不见的「最优」。

因此：甘特的行是款色/指令，列是工作日，条是工序窗。没有产线档案就不做分道。

## 4. 对象：什么时候存在什么

```text
销售色码（已接单）
  └─ 未排数量仍在订单上          ← 确认接单后；无执行单
        │
        │  放入甘特（草稿条，可换方案、可拖）
        ▼
排产草稿（计划：窗口 + 合单来源 + 负荷）  ← 仅排产页；确认前不占 allocated
        │
        │  人点「确认方案」
        ▼
执行单头 XE-… + 码明细 + 工序日           ← 车间只认这张
        │
        ▼
开裁 / 领料占用 / 报工 / 入库             ← 执行单页
```

| 对象 | 回答的问题 | 确认前 | 确认后 |
|------|------------|--------|--------|
| 待排款色 | 还没下发的需求 | 在 | 已排部分从待排消失 |
| 排产草稿 | 这张图是否被接受 | 在（可丢弃） | 变为已确认计划，不再当第二账本 |
| 执行单 | 车间这张活 | **不存在** | 出现；与甘特已下发条同一份 |
| 需求缺料 | 这张客户单还缺什么 | 接单后即可算 | 仍可看；采购不依赖执行单 |
| 生产缺料 | 这张车间活缺什么 | 无（预览可只读估算） | 绑执行单头 |
| 锁库存 | 这张活是否独占池 | 不锁 | 默认可不锁；开裁/领料占用 |

**硬规则：** 排产草稿未确认，禁止 `create_execution`。禁止用「确认排产」内部偷偷建草稿并立刻确认来跳过计划。

「已排待开裁」= 执行单状态 `confirmed`（已下发、未开裁）。是筛选，不是第二种单据，也不是排产页上的第二张表。

## 5. 默认路径（人怎么走）

打开 `/admin/schedule`：

```text
① 待排抽屉：勾本周要做的款色（一行一款色，码只展示合计，整行勾选）
     可软排缺料；齐套仅作过滤，不是进场门票
② 一键出方案：三条策略写进同一张甘特（默认落在引擎推荐的那套）
③ 顶栏切换：保交期 | 保现场 | 只排齐套
     条子、逾期、超产、缺料当场变；不是三张评分卡弹窗当主交互
④ 不对就改：拖整单或某道工序；顶栏负荷跟着变
⑤ 确认方案
     提示：将下发 N 张执行单 · 工序按图上日期写入 · 不锁料
     成功后留在甘特：这些条变为「已下发」
     Toast：已下发 XE-…。下一步：开裁
⑥ 点已下发条 → 同一张执行单（开裁）
```

日常改期、插急单：仍在这张甘特上动，确认冲击后再写。不另开「智能排产」入口。

**一次确认的含义：** 接受眼前这张图。同时发生：合单落执行单 + 写工序窗口。不是先下单再排，也不是排完再复制一张单。

## 6. 生产甘特（默认画布）

做**指令甘特**，原因是厂里通常没有可信的线别主数据；不是因为竞品不做或旧评审砍过甘特。

| 维 | 规则 |
|----|------|
| 行 | 款色（确认前=草稿条；确认后=执行单头）。同款同色多销售来源合在一行 |
| 列 | 工作日（尊重厂休/加班/停工日） |
| 条 | 裁 / 针车 / 成型 / 包装（按产品工艺；无则按租户工序） |
| 顶栏 | 瓶颈工序（默认成型，可改）的日负荷；≥预警阈值黄，超产红 |
| 条上标记 | 缺料 / 预计齐套日 / 逾期 / 急单 / 已下发 |
| 改 | 拖动整单平移，或拖某道工序改窗口；系统重算相邻工序，刷新负荷与冲突。已开裁的条不可拖开工日 |
| 空状态 | 空甘特 + 待排抽屉，而不是先逼用户理解「生成草案」 |

切换策略 = 用另一套规则重算**未确认**的条；已下发且已开裁的条不动。已下发未开裁的条：策略切换可给出冲击预览，需再次确认才改日期。

周负荷、月历不是并列 Tab。负荷在甘特顶栏；需要看四周时可展开，不离开这张图。

## 7. 三套方案（策略，不是三个产品）

沿用现网规则引擎的三种排法，产品名对人可读：

| 人看到的 | 引擎 `strategy` | 取舍 |
|----------|-----------------|------|
| 保交期 | `delivery_first` | 倒排赶交期；可能超产、加班 |
| 保现场 | `capacity_first` | 正排、避开超产；部分单可能更晚 |
| 只排齐套 | `kit_ready` | 缺料不上图（或留在待排）；计划更可开裁 |

方案对比的数字（逾期件数、负荷峰、超产天数、跳过的缺料款）挂在策略切换旁，一点就懂为什么推荐哪套。采用 = 当前甘特换成那套，仍可拖。

不在主路径上再套「生成倒排草稿 / 未确认草稿列表 / 智能方案弹窗」三步。

## 8. 确认下发 × 执行单

确认后：

- 同款同色挂**一张**执行单头；码是明细；多销售来源写分配比例。  
- `allocated_qty` 此时才增加；待排池减少。  
- 工序 `start_date` / `end_date` = 甘特上人看过的窗口（含拖改后的）。  
- 不锁库存、不派工。  
- 销售头进入履约中（若尚未）。

执行单页：

- 列表只有这一份。状态筛：待开裁（`confirmed`）/ 已开裁 / 生产中 / 已完成。  
- 日常合单在排产确认里完成。执行单「补码/合单」降为紧急入口，不当排产。  
- 开裁卡首道齐套硬闸。

排产页**删除**「已排待开裁」独立列表。已下发未开裁的活：在甘特上用状态区分，点击进入执行单。

## 9. 缺料与锁库存（与排产正交）

```text
确认接单
  → 需求缺料（绑销售单/色码）→ 可下长周期采购 → 到料进共享池
  → 不锁库存

排产预览 / 甘特
  → 只读：若下发，缺什么、齐套日、是否与已下发单争料
  → 不是生产缺料单，不是锁库

确认方案 → 执行单
  → 生产缺料汇总（绑执行单头，合单后才准）
  → 默认不锁

开裁前 / 领料
  → 日常：领料一步占用（锁料 UI 默认关）
  → 料紧、急单、抢料：才手工锁到执行单头
  → 开裁：首道齐套硬闸
```

钉子、锤子等备库料不进这两张缺料账。

软排：缺料可以出现在「保交期 / 保现场」图上，条须标明齐套约束；开工日不得早于齐套日（P0 已立的硬约束，确认时同样生效）。「只排齐套」则不上这些款。

## 10. 信息架构（只留一个排产）

侧栏：

| 入口 | 职责 |
|------|------|
| 生产 → **排产** | 唯一智能排产：待排 + 甘特 + 确认下发 |
| 生产 → **执行单** | 车间单据：开裁、缺料、领料、报工、入库 |
| 车间军师 | 只解说、只仿真；不写计划、不下发 |

排产页内部（目标态）：

- 主画布：甘特  
- 左或底：待排款色抽屉（可收）  
- 顶：策略切换 + 对比数字 + **确认方案**  
- 计划设置（日历、日产能、负荷阈值）仍是设置，不是排产本身  

**取消作为并列主入口：**

- 「选款下生产」独立 Tab（并入待排抽屉）  
- 「已排待开裁」独立 Tab  
- 「改工序日」独立 Tab（改日 = 拖甘特）  
- 「智能方案」独立弹窗作为主路径（对比数字改挂策略切换）  
- 「周负荷 / 日历」独立 Tab（并入甘特）  

过渡期若引擎仍要旧 pool API：藏在设置或 `?legacy=1`，文案不得再叫智能排产。

## 11. 现网能力怎么用（最后才映射）

实现时优先复用，而不是先改表。产品形态以本文为准，下列都是零件：

| 现网 | 用在目标态 |
|------|------------|
| `list_producible` / `color-pool` | 待排抽屉数据 |
| `generate_proposals` 三策略 + `risks`/`load` | 策略切换与对比数字 |
| `_backward_windows` / 日历 / 停工日 | 甘特落条与工作日 |
| 周负荷 API | 甘特顶栏 / 展开四周 |
| 插单仿真 | 甘特上插急单的冲击预览 |
| `create_execution(..., header_id=)` 同款同色一头 | 确认下发 |
| 执行单列表 + 开裁 | 执行单页 |

**必须改掉的行为：**

- `POST /schedule/confirm-production` 先 `propose_draft` 再立刻 `confirm_draft`、人看不见计划。  
- 智能方案只挂在「改工序日」、且要求已有执行单/遗留生产单才能算。目标态：输入是待排款色（虚拟活），确认前没有 `header_id`。  
- 排产页再 list 一遍 `status=confirmed` 的执行单。

引擎若仍以 `order_ids`/`header_ids` 为输入：实现切片里要能把「待排款色勾选」编成一次可排的虚拟任务集，确认时再 `create_execution`。不要为了迁就旧主键，先下发再排。

## 12. 正确的事（验收时不可退让）

1. 确认的是计划，草稿与下发数据不得只差一个 status。人必须看见日期/负荷/冲突。  
2. 未确认不得出执行单，不得占 `allocated_qty`。  
3. 智能排产只出现在排产页一次。  
4. 执行单与「已排待开裁」同一对象；列表只维护一份。  
5. 人确认才写库；策略切换、拖条、仿真都不落正式指令。  
6. 缺料可软排；开裁卡首道齐套。  
7. 接单不锁库；排产确认不锁库。  
8. 已开裁交期/开工不得被策略切换静默改。

## 14. 走查脚本（目标态）

| # | 步骤 | 期望 |
|---|------|------|
| 1 | 确认接单，不打开排产 | 无执行单；需求缺料可算；待排可见该款色 |
| 2 | 排产：勾两张销售单的同款同色，出方案 | 甘特一行；三套可切换；仍无 XE |
| 3 | 不确认，去执行单页 | 仍无这张单 |
| 4 | 切到保现场，拖开裁日，确认 | 一张 XE；工序日=图上日期；allocated 增加 |
| 5 | 待排少了这些数量；甘特条为已下发 | 点条进入同一张执行单 |
| 6 | 执行单筛「待开裁」 | 就是这张；不是第二份数据 |
| 7 | 缺料款走保交期 | 可上图并标齐套日；确认后仍不锁料；开裁被首道齐套拦住 |
| 8 | 已开裁后再切策略 | 该条日期不变 |

## 15. 开放问题（不阻塞 S0/S1）

- 甘特第一版是否支持拖单道工序，还是先只允许拖整单/改开裁日（相邻工序按路线重算）。建议 S3 先整单+开裁日，单道拖随后加。  
- 待排抽屉默认打开还是甘特为空时打开。建议有未排且图空时打开。  
- 产线档案达标后，行是否改为线（AU-I3plus）。默认仍按款色行。
