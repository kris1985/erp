## 0. 问题

不是缺功能，是**现场主码没立住**：

- 竞品：指令/流程卡一码，扫了就报。  
- 现网：工位码 + 捆标 + 合批卡 + 流转卡（B0b 不可扫）并存 → 教错。  
- 根因：用「双入口都能报」凑合，而不是规定货上只认一种主码。

**同号一体** = 一体在跟着货走的卡，不是合批号 / 排产号 / 工位号。

## 1. 产品定稿（正确事）

### 1.1 同号一体（必达）

```text
货上主码 = TraceUnit.code（一码一捆）
工人日常：只扫这一码 → 报工 / 过站 / 不良 / 追溯
PMC/裁床：开裁生成 TraceUnit 并「一单多码」打印，码贴到对应捆上
工序上下文：开追溯后优先由工位码提供 process_id（工位不定货、不选单）
```

| 对象 | 定位 | 日常报工扫码 |
|------|------|--------------|
| **货上主码（TraceUnit）** | 现场唯一**身份** | ✅ |
| **工位码** | 只定**本工序**；无主码时的选单兜底 | ❌ 不作货身份 |
| **合批卡** | 合刀协同纸面 | ❌ |
| **排产草稿号** | 计划 | ❌ |

### 1.2 分层（保持）

| 层 | 对象 | 职责 |
|----|------|------|
| 账本 | 生产单 `orders` | 齐套/领料/派工/报工/出货/成本 |
| 协同 | 合批 | 一起干；**不报工、不分摊** |
| 计划 | 排产草稿 | 日期 + **整工序**粗派人 |
| 细派 | 订单按捆派工 | **可选**；有主码之后 |
| 身份 | `TraceUnit` | 货上主码 |
| 工序上下文 | `Station` | 开追溯后：定工序，不定货 |
| 来料质检 | B2d IQC | 采购 |
| 在制质检 | DefectEvent | 扫主码；B2g 反查 |

### 1.3 架构拍板（进 M1 前锁死）

| ID | 决策 | 定稿 |
|----|------|------|
| **D1** | 码粒度 | **一码一捆** = 一个 `TraceUnit` 一个二维码；禁止「整单一码」当主码（削弱色码/B2g/按捆） |
| **D2** | 打印形态 | **一单多码**：B0b 升级为「本单主码打印页」（按色码行/捆策略列出多枚码）；对外仍可叫流程卡/捆扎卡 |
| **D3** | 工位角色 | **工位只定工序**：扫主码带出单/色/码/捆；`process_id` 来自当前工位绑定，缺工位时再选手动选工序。工位**不是**开追溯后的选单主入口 |
| **D4** | 与报工后自动起捆 | 开追溯且本单已走「开裁生码」后：报工路径 **不得**再 `create_bundle_from_work_log` 静默平行生码 |
| **D5** | 合批执行 | 合批卡永不带报工码；合批页提供 **成员派工 + 成员打主码**（减点击，账本仍分单） |
| **D6** | 主码生命周期（M1 最小） | 生成 → 打印/补打**同码** → 报工/不良；支持作废（作废后不可报工）；禁止无策略重复灌水生码 |

**竞品关系：** 抄的是「扫货上卡即报」；一码一捆 / 一单多码是本系统为 TraceUnit+B2g 做的正确落地，不是每家垂直的字面形态。

## 2. 标准作业（对外唯一 SOP）

### 2.1 开追溯（默认）

```text
① 合批（可选）→ 打合批卡（不扫报工）
② 排产确认 → 日子 + 整工序粗派人
③ 开裁 → 生 TraceUnit + 一单多码打印 → 贴到各捆
④ 工人扫货上主码（可选：所在工位只定工序）→ 报本工序
⑤ 可选：订单按捆细派（有卡之后）
⑥ 质检扫同一主码 → 不良 / 追溯 / 返修
```

**工人一句话：** 只扫鞋上的码。

### 2.2 不开追溯

- 可继续：工位码 + 选单报工。  
- 款打开 `trace_enabled` 后切换 §2.1，产品给切换提示。

### 2.3 合批

- 合批卡：成员单号 + 汇总色码 + 「报工扫各单货上主码」。  
- 从合批进成员派工 / 成员打主码。

## 3. 需求条目

### 3.1 同号一体（核心）

| ID | 需求 | 说明 |
|----|------|------|
| **B2h-R20** | 定义货上主码 | = `TraceUnit.code`；对外统称流程卡/捆扎卡 |
| **B2h-R21** | 开裁打卡即生码 | 生产单（或合批成员）一键按 **色码行默认一捆**（或指定捆量拆多捆）生成 TraceUnit 并进入打印；**不依赖**先扫工位报工 |
| **B2h-R22** | 扫主码即报 | 落地页预填单/色/码/捆；**工序：优先用工位 `process_id`，否则选手选工序**；禁止再搜生产单 |
| **B2h-R23** | B0b 合流 | 原流转卡打印改为 **一单多码主码页**；禁止不可扫平行纸长期并存 |
| **B2h-R24** | 工位身份降级 | 开追溯：禁止以「扫工位 → 选单」为日常主路径；工位用于定工序或无卡兜底（兜底须二次确认） |
| **B2h-R25** | 禁扫清单 | 合批号、排产号不可写 `work_log`；误扫人话提示 |
| **B2h-R27** | 自动起捆互斥 | 落实 D4：已开裁生码的追溯单，报工不再静默起捆 |
| **B2h-R28** | 补打与作废 | 落实 D6：补打同码；作废不可报 |

### 3.2 计划 / 派工 / 合批

| ID | 需求 |
|----|------|
| B2h-R1 | 排产确认：仅整工序；细派去订单 |
| B2h-R2 | 派工：整工序默认；按捆=有主码后加强；无码空态 →「去打货上卡」 |
| B2h-R5 | 合批 → 成员派工 |
| B2h-R5b | 合批 → 成员打主码（批量入口） |
| B2h-R6 | 合批卡脚注：勿扫合批号报工 |
| B2h-R7 | 主码打印含：生产单号、色码、数量、合批号（若有） |
| B2h-R8 | 开追溯 ≠ 强制按捆派工 |
| B2h-R9 | （可选）整工序 → 按捆配额草稿 |

### 3.3 质检 / 追溯

| ID | 需求 |
|----|------|
| B2h-R12 | 来料 IQC ≠ 在制不良 |
| B2h-R26 | 在制不良/返修/追溯主路径扫主码（无码=弱追溯，B2g） |
| B2h-R13 | 责任线索不进工资自动流 |

### 3.4 明确不做

| 不做 | 原因 |
|------|------|
| 整单一码当货上主码 | 与 D1/B2g/按捆冲突 |
| 排产草稿按捆/色码派工 | 计划应粗 |
| 合批号报工 / 批上自动分摊 | 多客合刀 |
| 开追溯后工位选单当日常主路径 | 违背同号一体 |
| 真合单账本（为本需求） | 过重；走 B3c 闸门 |
| 单双一码 / 视觉定责 | P∞ |

## 4. 验收标准

### 4.1 同号一体（必达）

| # | 标准 |
|---|------|
| E1 | 不经工位报工，能开裁生成 TraceUnit 并打出多枚主码 |
| E2 | 只扫主码完成合格报工（单/色/码/捆预填；工序来自工位或手选） |
| E3 | 同码登记不良 + 追溯台反查 |
| E4 | 开追溯日常 UI/话术不以工位选单为第一推荐 |
| E5 | 合批号不可报工（或误扫提示） |
| E6 | 补打同码；作废后不可报工 |
| E7 | 已开裁生码单：报工不再静默平行起捆 |

## 6. 对外话术

> 鞋上只有一个码（一捆一码）。排产定日子和粗派人；合批是一起干的纸；报工、不良、追溯都扫鞋上的码。工位只告诉系统你在哪道工序，不代替鞋上的码。
