| | 外部文档 | 本系统改写 |
|--|----------|------------|
| 定位 | ERP 内置粗排 → 精细日 APS → AI 全量重排 | **轻量可确认排产**：齐套闸门 + 工序倒排/正排 + 插单仿真 + 军师解说 |
| 一期 | 齐套 MRP + 粗周排 + 基础看板 | **打磨已有**：齐套日喂入开工、周负荷视图、风险/今日行动串联 |

| 依赖 | 42 项数据全达标再开发 | 现有 BOM/工序/可选日产能即可出方案；核对表作**客户实施清单** |

## 2. 改写版一期 backlog（仅「改」项）

> 与主稿 [`aps-dev-review.md`](./aps-dev-review.md) §六一致；启动判定见主稿 §2.1 / §2.2。

| # | 项 | 验收（可量化） | 主要触点 |
|---|-----|----------------|----------|
| P0-1 | 生产单计划窗口尊重 `kit_ready_date` / ETA | 缺料单不会排出「齐套日前开工」；测试覆盖 | `schedule_engine` |
| P0-2 | 齐套日 / ETA 在缺料、齐套 Tab、风险条口径一致 | 同单三处日期一致或明确「无 ETA」 | material / orders UI |
| P1-1 | 负荷按自然周汇总（瓶颈工序视角） | PMC 能回答「本周 / 下周超载几天」 | `ScheduleAdminView` + `/load` |
| P1-2 | 「今日可排」→ 一键出方案 | 工作台行动一点到 proposals 预填池 | A0 ↔ schedule |
| P1-3 | 风险根因进今日行动 / 军师 | 「谁最危险」引用风险码+齐套日，不口编 | `workshop_metrics` / today_actions |
| P1-4 | 排产池可按合批筛选（若 B2f 已上） | 同批多单一并进池可见 | pool API + UI |
| P1-5 | 缺料工单批量筛选导出 + 企微推送 | Excel：款号、缺料物料、预计齐套日、风险等级 | 待排池/缺料批量操作 |
| P1-备选 | 低峰预计算方案缓存（不落库） | 人点重算可快速加载预生成结果 | 后台任务 + proposals |
| — | B2a / B3a | 完整率≥95% + 顾问签字后才进二期 Backlog | 主稿 §2.1 |
| — | 合批损耗差值 | 领料+完工实耗报工闭环后再做 | 主稿 §2.2 |

**明确不进本期：** 甘特、换模引擎、模具独占、外协分流周计划、OCR 录单证明 AI、5 分钟全自动重排落库。

## 3. 验收指标（替换文档偏 APS 的数字）

| 阶段 | 文档原指标（慎用） | 改写验收 |
|------|--------------------|----------|
| 一期 | 齐套≥98%；周负荷误差≤5%；缺料提前≥3 天 | ETA/齐套日三处一致；齐套日前不可确认开工；方案→确认路径；周负荷可答；**今日行动缺料提前≥3 天可见**；PMC 路径步骤目标约 −60%（抽检）；P1-5 导出 |
| 二期 | 日排程少改、10 分钟重排、利用率+10%、延期−30% | **不承诺**；人点重算 + 可选预计算；B2a/B3a 达标后提示有效 |
| 三期 | 合批降损耗 2%–4% | 实耗回写达标后再立指标 |

**实施投产闸门：** 核对表签字前仅演示模式；签字后才正式启用排产确认（见主稿 §三）。
