## 1. 总判

| 维度 | 结论 |
|------|------|
| **业务洞察** | **合适**：裁断合批 vs 成型合单要分开；HITL；成套/禁跨材质；合产分算、出货按原单——与行业与总纲原则一致 |
| **与现网** | **部分已落地（B2f = 合批不合单）**；草案把「母工单 + 批次领料/报工/成本」写成一期 P1 → **与架构冻结冲突** |
| **可借鉴** | 匹配规则作**推荐条件**、排产池按批筛、合批纸面（分床单/卡）、今日行动「可合批」提示；**不**借母工单账本 |
| **路线** | 继续走总纲梯子：**L1+L2（已 ✅）→ 排产按批筛 →（闸门后）B3c 真合单**；不要把四层「主流鞋业完整合单」压进一期粗排 P1 |

一句话：**想法在行业上对，在分期上把「真合单」误标成了「一期合批」；现网正确姿势是合批挂多生产单，账本仍认 `orders.id`。**

## 2. 概念对齐（避免混名）

| 草案用语 | 总纲 / 现网用语 | 现状 |
|----------|-----------------|------|
| 裁断合批（同皮料多款合刀） | 行业刚需；现网 **未**按「同料」聚类 | B2f 硬条件是 **同款 `own_product_id`**（默认同色），不是同皮料编码 |
| 成型/针车合单（同底模/楦） | 接近 **真合单 B3c** + 依赖 **B3a 楦模** | 未做；模具档案挂 B3a |
| 合并母工单 + 源单不可单独领料 | **真合单 / 可产池**（§1.4 闸门） | **禁止**在闸门前做 |
| 合批流转卡 / 勾选组批 | **B2f L1+L2** | ✅ 已上：组批 + 汇总色码 + 合批卡 |
| 排产自动合批推荐 | 粗排 **推荐 + HITL**；非静默合并 | 引擎尚无合批维；APS 稿 P1-4 = **按已有批筛选** |

## 3. 草案分层 vs 现网：合适 / 冲突 / 可借

### 第一层 · 匹配规则

| 草案点 | 判定 | 说明 |
|--------|------|------|
| 裁断：同料编码/色/厚、交期窗、齐套闸门 | **合适（规则库）** | 可作推荐筛选；**不能**当一期强制合单条件——缺「跨款同料」模型与厚度主数据 |
| 成型：同款/同底模/同楦/同工艺 | **合适但挂依赖** | 无 B3a 无法硬校验底模/楦；同款已由 B2f 覆盖一部分 |
| 只推荐不自动合并、禁跨客户锁单、最小批量阈值 | **合适，可借鉴** | 与 HITL / 排产红线一致 |
| 尺码成套、禁跨材质、溯源财务 | **合适（原则）** | 成套/出货分单已是产品立场；跨材质合批现网未做「同料合刀」故暂无此坑 |

### 第二层 · 操作模式

| 草案点 | 判定 | 说明 |
|--------|------|------|
| 模式 A 勾选合并 | **已有近似** | = B2f 组批；**不是**生成母工单、不是锁源单领料 |
| 「原工单已并入不可单独排产/领料」 | **冲突** | 违反冻结：齐套/领料/报工/排产认 `orders.id`；B2f 验收明确「仍分生产单」 |
| 模式 B proposals 输出合批方案 + 损耗降幅 | **部分可借** | 推荐/分组可做；**损耗降幅**依赖实耗闭环（APS §2.2 挂），不宜作 P1 验收硬指标 |
| AI 不自动合并 | **合适** | 已是红线 |

### 第三层 · 全链路流转（草案核心难点）

| 草案点 | 判定 | 说明 |
|--------|------|------|
| 合并领料单：总行 + 源单分摊明细 | **冲突（一期）** | = 批次领料；总纲 B2f 明确不做；属 B3c/账本升级后 |
| 合批裁断分床单（纸面） | **可借鉴（轻）** | 可用合批卡/打印扩展「汇总用料建议」（只读加总各单需求），**不下推一张批次 StockDoc** |
| PDA 报工双写母单+源单 | **冲突** | 无母单主体；报工已在源单；强制分摊报工属 P∞/闸门后可选 |
| 成型合单强制成套上线 | **原则合适，实现靠后** | 现有分单报工+出货隔离已部分达成「合产分交」叙事 |
| 入库出货按原销售单 | **合适且已守** | 禁止合批直接出货 |
| 成本按比例分摊 + 母单溯源台账 | **冲突（一期）** | 无母单；成本仍在分单；真合单闸门后才谈全账本主体 |

### 第四层 · 报表与今日行动

| 草案点 | 判定 | 说明 |
|--------|------|------|
| 待合批汇总、工作台提醒 | **可借鉴** | 基于 B2f「同款同色可组未组」或未来「同料」规则；低成本 |
| 合批 vs 分开损耗对比表 | **挂** | 同 APS 合批损耗：要领料+实耗回写 |
| 合单成本分摊明细导出 | **挂 B3c 后** | 一期无母单分摊引擎 |

## 4. 与智能排产一期的关系（纠正草案「P1」标注）

草案把「母工单 + 合并领料 + proposals 合批维」标成一期 P1 —— **与下列文档矛盾**：

- 总纲：P1 **不合批不合单**；合批在 **P2-Next B2f**（已 ✅）  
- APS 整合稿 P1-4：排产池 **按已有合批筛选**（展示/成组），不是新建母工单  
- APS P1-5 已占用「缺料导出」；草案另起的「P1-5 合批领料」应改名且 **降级或后置**

**排产侧建议保留的合批相关项（不破冻结）：**

| 项 | 内容 | 不做 |
|----|------|------|
| 排产池按 `merge_batch_id` 筛 | 同批多单一起看、一起进方案勾选 | 批次成为排产主体 |
| 软推荐「可组批」 | 同款同色未入批 → chip / 今日行动 | 静默合并、改 proposals 主算法为合批优化器 |
| 合批卡/分床纸面增强 | 成员需求加总只读打印 | 批次领料单据 |

## 5. 架构冲突清单（不得按草案原文开工）

1. **母工单成为领料/排产/进度主体** ↔ 冻结主体 `orders.id`  
2. **「已并入则不可单独领料/排产」** ↔ B2f「账本仍分单」验收  
3. **同皮料跨款合刀** ↔ 当前 B2f 仅同款；需新匹配维，且勿与真合单绑死  
4. **底模/楦校验合单** ↔ B3a 未齐前无硬数据  
5. **把完整四层标成一期粗排 P1** ↔ 总纲梯子与 APS「砍精 APS」一致立场下的错误分期  
6. **损耗下降值进一期验收** ↔ 实耗数据未闭环（§2.2）

---

## 6. 可直接吸收的借鉴点（建议采纳）

1. **业务二分法写进话术**：裁断合刀（降损耗）≠ 成型合单（降换模）——售前与 PMC 培训用。  
2. **HITL + 禁止静默合并 + 出货永不按批**——已一致，保持。  
3. **匹配规则配置化（开关）**：先做「同款同色 + 交期窗 + 齐套」推荐；同料/同厚作二期规则扩展。  
4. **纸面协同优先于账本升级**：合批卡 / 分床计划（只读汇总）解决现场 80%「合刀靠 Excel」痛点——B2f 已走通，可小步增强。  
5. **今日行动「可合批未组」**——对接 A0，成本低、与排产叙事一致。  
6. **路线 1 vs 路线 2**：草案第五节与 APS「轻量规则 vs P∞ 深合批」一致——确认选路线 1。

## 7. 建议分期（取代草案「一期四层」）

| 阶段 | 做什么 | 对应 |
|------|--------|------|
| **现网** | 同款（同色）组批 + 合批卡；领料报工出货分单 | B2f ✅ |
| **近端** | 排产池按批筛；可组批推荐/今日行动；合批卡用料只读汇总（可选） | APS 池筛 + A0；**非**母工单 |
| **B3a 后** | 同底模/楦冲突**提示**（仍可不合单） | 提示 ≠ 独占 APS |
| **同料合刀（若客户强需求）** | 独立「裁断合刀推荐」：跨款同料聚类，仍只组**执行批/纸面**，账本分单 | 新产品切片，勿冒充 B3c |
| **闸门后 B3c** | 可产池、色码分配、主体升级、合并领料/成本分摊、可选报工分摊 | §1.4 六条全勾 |

## 8. 结论落款

- **合适：** 行业规则、HITL、合产分算分交、轻量规则路线、报表/行动提醒方向。  
- **冲突：** 母工单账本、批次领料/双写报工、源单锁死、把上述标为粗排一期 P1。  
- **借鉴落地：** 在 B2f 之上做「筛/荐/纸/行动」；真合单严格走 B3c 闸门。  
- **否决：** 按草案第三层原文作为本期排产/合批开发范围。

## 9. 补充问答：行业「合版/合单」四件套是否正确 · 楦底模 · 何时合 · 挂谁

> 来源：另一份「规则引擎合单 / Nesting / 条码拆分 / 成本分摊」行业分析（2026-08-09）

### 9.1 那份分析对不对？

| 模块 | 判定 | 说明 |
|------|------|------|
| 同料/色合并裁断、同楦/底模合并成型 | **方向正确** | 行业两类合批，与本文 §2 一致 |
| 配码打通成一张大派工单 | **半对** | 汇总色码 ✅（B2f 已做）；「打成一张派工单主体」= 真合单，闸门前不做 |
| 采购输出合并总需求 | **对，且可轻做** | 缺料/采购建议按料加总即可，不必先有母工单 |
| CAM 合版 Nesting 降损 3%～8% | **行业真，产品勿承诺** | 属裁床/CAM；ERP 最多给「同料件清单+用量」，不上排版引擎（P∞ 视觉/排版类） |
| 大派工 → 捆扎卡按原单拆分追踪 | **对，且现网已近似** | B2f 合批卡 + 分单报工/捆标；不是先造虚拟母单再拆 |
| 材料按 BOM 面积分摊、前合后分计件 | **财务上对，工程上后置** | 闸门前成本在生产单；强上合并分摊易与计件锁价打架 |
| 交期窗 / 客户等级禁合 / 缸号色差 | **约束正确，应进推荐规则** | 缸号依赖库存批次，现网批次深度有限，先交期窗+客户锁 |

**总评：** 像「成熟垂直 ERP 能力百科」——**业务正确、边界过大**。对你们：取约束与追踪叙事，拒 Nesting/母单成本引擎作近端范围。

### 9.2 要不要上底模 / 楦头？

| 问题 | 结论 |
|------|------|
| 要不要主数据？ | **要，但是 B3a 轻量档案**（款↔楦/底模/刀模，可用数量），不是排程独占 |
| 要不要用来**自动合单**？ | **先不要**。无档案硬合单会瞎合；有档案先做「同楦/同底模可合」**提示** |
| 何时进合批硬校验？ | 主力款覆盖率 ≥95%（与 APS §2.1 同口径）后再谈成型合单推荐 |
| 与排产关系 | 抢楦冲突提示 ≠ 模具 APS；仍挂 B3a，不进一期粗排必交付 |

**产品顺序：** 先 B2f（同款合刀纸面）→ 排产按批筛 → **B3a 楦底模档案** → 同楦/底模推荐 →（认领）B3c。  
**不要**为了「一次装模大批量」提前上母工单。

### 9.3 什么时候合？销售下达时 vs 后面再合

| 时机 | 适用 | 本系统建议 |
|------|------|------------|
| **销售确认时就合** | 极少；仅预测单/内部备货提前合刀 | **默认不做**。交期/齐套/客户锁未稳，早合易绑死、难拆 |
| **齐套后、投产前（PMC 排产窗）** | **主流** | **推荐主路径**：料齐（或首道齐）+ 交期窗内 → 推荐组批 → HITL |
| **裁断当天现场合** | 老师傅合刀 | 系统侧用合批卡/分床单协同；账本仍分单 |
| **成型上线前再合** | 同楦/底模连续做 | 依赖 B3a；仍建议挂**生产单组**，不是改销售单 |

**原则：合在执行计划层，不合在商务接单层。**  
销售单保持客户/交期/价格真相；合并是 PMC 对**已确认可产**对象的操作。

### 9.4 合批/合单关联销售单还是生产单？

| | 关联 **生产单 `orders.id`**（现网） | 关联 **销售单/销售行** |
|--|-------------------------------------|------------------------|
| 现网 | ✅ B2f `merge_batch_members.order_id` | 经 1∶1 可回查销售，但批成员不直接挂 SO |
| 齐套/领料/报工/出货 | 已认生产单 | 若批只挂 SO，与执行账本断裂 |
| 无销售行的独立生产单 | 可入批 | 挂 SO 覆盖不了 |
| 真合单（远期） | 可产池仍从生产/分配来，销售靠**分配表**回写 | 销售仍是分账，不是合并主体 |

**结论（写死）：**

1. **近中期（含 B2f）：合批只关联生产单**；销售单保持 1∶1/分账，作出货与应收真相。  
2. **禁止**「合并销售订单」当生产指令——商务变更、分批发货、验货会乱。  
3. **远期 B3c：** 指令可多来源，但必须有**色码分配表**把产量/出货/成本拨回销售行；不是取消销售单，也不是让合批直接出货。  
4. 若口头说「合单关联销售单」，正确含义是：**通过生产单溯源到销售单**，不是批头 FK 销售单。

### 9.5 决策一览（可贴评审）

```text
分析百科：业务对，近端范围过大（尤其 Nesting / 母单成本）
楦/底模：上档案（B3a），先提示后合单；不上模具 APS
何时合：齐套后、排产/投产前 HITL；不在销售下达时默认合
挂谁：合批 → 生产单；销售单只溯源、不分摊执行主体
追踪：大卡/合批纸面 + 分单捆标报工（已有方向）；先不造虚拟母工单
```

## 10. 拍板：近中期用合批；报工与成本怎么做

| 问题 | 答案 |
|------|------|
| 用合单还是合批？ | **近中期只用合批**；合单=真合单 B3c，闸门前不开发、不主推 |
| 如何报工？ | **按生产单**（色/码/工序）报；合批卡只辅助选对单；禁止默认「报在批上再自动拆」 |
| 如何分摊成本？ | **先不分摊引擎**：领料/计件落在各生产单；批维度只做**只读汇总**；合并领料再按面积摊 = B3c 后 |
| 财务红线 | 出货/应收**永不按批**；批号最多备注 |

```text
销售单（分账）──1∶1──► 生产单（齐套/领料/报工/出货/成本）
                         │
                         └──成员──► 合批（纸面+筛选+汇总）← 不领料、不报工、不出货、不分摊
```

## 11. 合单与合批能否并存 · 和排产引擎的关系

| 问题 | 结论 |
|------|------|
| 以后上合单是否与合批冲突？ | **模型上是升级，不是永久双主路径**。合批组可升级为合单指令；禁止同一活两套领料/两套卡 |
| 两者同时常用会否太复杂？ | **会**——若对等卖两个入口。定位必须是：合批=默认；合单=认领制高级能力 |
| 中小厂更适合哪个？ | **合批**（实施低、贴现场）；真合单非标配 |
| 与排产引擎？ | **合批弱关联**：池按批筛/成组，引擎仍排 `order_ids`。合单若上，优先仍排成员/分配行，勿轻易改引擎主体为「母单」 |
| 合批推荐 vs 排产 | **双引擎、同计划中心、共享交期窗/日历**；荐批 ≠ 排日子；皆 HITL，禁静默落库 |

## 12. UI 入口：生产订单 vs 排产池

> 现网 B2f 主路径在 `/admin/orders`；计划智能化后应调整主辅，**不是整锅搬走**。

| 入口 | 定位 | 适合动作 |
|------|------|----------|
| **排产池（主入口 · PMC）** | 计划型合批 | 可合批推荐、交期窗筛选、勾选采纳组批、按批筛后出方案 |
| **生产订单（辅入口 · 跟单/执行）** | 执行型合批 | 临时组批、合批管理、打印/补打合批卡、移出成员 |
| 合批详情/打印 | 共用 | 两边可进 |

**原则：** 订单页保留组批/打卡合理；**智能推荐与「先合后排」闭环长在排产池**。避免两套对等主路径抢心智。

详见 [`B2f-merge-batch.md`](./B2f-merge-batch.md) §入口演进。
