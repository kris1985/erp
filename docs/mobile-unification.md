# 手机端统一迁移约定

## 目标

- `uniapp/` 是唯一继续开发的手机现场端，一套源码输出 H5、Android/iOS App。
- `web/src/views/admin/` 与 PC 打印/看板页面继续由 Web 维护。
- `web/src/views/` 现有手机页面进入兼容维护：只修阻断问题，不再新增业务能力。

## 发布入口

- PC 管理台：`/admin`
- 统一手机端 H5：`/mobile/`
- UniApp H5 使用 hash 路由，页面地址形如 `/mobile/#/pages/home/index`。
- 原生 App 打包必须设置 `VITE_API_BASE_URL=https://实际域名/api/v1`；同域 H5 默认使用 `/api/v1`。

## 迁移规则

每个旧 Web 手机页面按以下顺序退出：

1. UniApp 页面达到功能、权限、错误提示和扫码回跳一致。
2. H5 与 App 各完成一次真实设备走查。
3. 将旧 URL 改为跳转 `/mobile/` 对应页面，并保留查询参数/扫码对象。
4. 至少保留一个发布周期的兼容跳转，再删除旧 Vue 页面。

禁止直接删除旧页面或一次性把所有手机路由切走。

## 页面迁移批次

### M1：扫码闭环（已具备主体）

- 登录、首页、我的计件、我的工资、个人中心
- 工位码、框/捆码、流转卡、箱唛
- 箱唛报工 → 入库 → 出库

### M2：主管现场作业

- 主管工作台（✅ 已迁入；含客供到货与 IQC 判定）
- 订单/执行进度（✅ 已迁入只读进度与工序展开）
- 班组与代报工（✅ 框/捆码批量代报、成员搜索/加入/移除均已迁入）
- 线报工（✅ 已迁入）
- 采购到货（✅ 已迁入）

### 上线安全项

- 首次登录/密码重置后的强制改密（✅ H5 与 App 均接入）

### M3：兼容链接收口

- 旧 `/scan`、`/trace`、`/flow-card`、`/carton-report` 链接跳转 UniApp
- 旧 `/home`、`/my-work-logs`、`/my-salary` 等手机路由跳转 UniApp
- 删除不再被引用的 Web 手机组件与 Vant/扫码依赖（PC 若仍使用则保留）

## 验收底线

- 纯员工、组长、仓管、经理四类账号权限一致。
- H5 和 App 扫同一张二维码得到同一业务对象和闸门结果。
- 401 会清理本端会话并回登录页。
- 箱唛重复报工、重复入库、重复出库均被拦截。
- App 离线、弱网、相机拒权时有明确提示，不产生重复单据。
