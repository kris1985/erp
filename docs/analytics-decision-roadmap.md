## 1. 产品原则（已定稿）

| # | 原则 | 含义 |
|---|------|------|
| 1 | 先辅助拍板，再谈预测 | 厂长/PMC/销售要的是「接不接、催哪料、今天排谁」，不是又一张大盘 |
| 2 | 确定性账本不动 | 齐套、库存池、工资、利润记账仍走规则；数据能力只提供风险分、ETA、情景对比 |
| 3 | 鞋业杠杆优先 | 色码曲线、底/面料长交期、争料、旺季插单、外发饱和 |
| 4 | 军师只做参谋 | 问数走指标；关闭 AI 诊断仍可用；确认生产/排产落库必须 HITL |
| 5 | 高频决策不堵 AI | 接单打开即出左栏；改假设只刷左栏；追问才打军师 |

## 3. 差距总览（按四条线）

### 3.1 数据分析（算什么）

| 主题 | 已有 | 缺口 |
|------|------|------|
| 接单即时诊断 | 色码/争料/实耗/冲击/回款规则分 | 色码按「楦/客户」分层仍粗；实耗样本少时可信度提示弱 |
| 产能 | 配置产能 + 粗校准文案；假设日产能 | 报工时序真值（滚动分位、星期效应、学习曲线）未做 |
| 齐套 / 到料 | 规则 ETA（PO/供应商粗估） | 供应商提前期分布、齐套预计日全链路挂载、逾期分 |
| 交期风险 | `at_risk` 规则 | 逾期概率排序（特征 + 后续 sklearn） |
| 争料 / 安全库存 | 接单争料矩阵 | ABC-XYZ、消耗速度、安全库存建议未产品化 |
| 质量 | 工序不良率汇总 | 多维交叉（工人×款×责任工序）、产量冲刺相关、爆发预警 |
| 流转 / WIP | 瓶颈剩余量 | `trace_unit_logs` 转移矩阵、停留分位未用 |
| 财务预测 | 毛利估算 + 回款规则标签 | 预估毛利区间、账龄迁移、放货策略未产品化 |
| 批价 | intake 内实耗偏差块 | **报价/批价入口**无「同类款实绩」面板（Polars 聚合） |

### 3.2 使用入口（在哪点）

| 入口 | 已有 | 缺口 |
|------|------|------|
| 销售单 · 生产分析 | ✅ 左主右辅 | 左栏视觉仍可打磨；空数据态引导（无 BOM/无历史）可加强 |
| 报价 / 批价确认前 | ❌ | 无独立批价决策面（P1） |
| 工作台看板 | 今日关注计数 | **无「今日 3 件事」行动卡** |
| 缺料 / 采购 / 齐套 Tab | 缺料表、催办 | 预计到料日/齐套日列未统一；争料保单操作未落地 |
| 生产订单列表 | 进度/风险标签 | 订单风险条（分数+原因）未做 |
| 排产页 | 方案/负荷/日历 | 方案对比话术与「今日 3 件事」联动弱 |
| 车间投屏 / H5 | 产量与预警 | 不承载决策分析（保持轻） |
| 老板概览 | 急单/风险/缺料计数 | 不接 top3 行动（可后续） |

### 3.3 产线军师（怎么问）

| 场景 | 已有 | 缺口 |
|------|------|------|
| 接单追问 | ✅ 预制问题 + 不重复左表 | 情景对比结果卡片化（仍偏对话） |
| 今日行动 | 快捷 prompt | **开场无 top3 卡片**；答复未强制绑 evidence |
| 周/月简报 | 可 query | 无固定周报订阅/落地页 |
| 排产 | 生成方案 + 提醒确认 | 与看板 top3「可排」一键串联不足 |
| 产能校准记忆 | `suggested_memories` | 用户感知弱（是否写入不直观） |
| 权限 | `today_actions` 要 `menu.orders` | 仅有排产权限的用户可能拉不到今日行动 |

### 3.4 辅助决策（拍板闭环）

| 决策 | 已有辅助 | 缺口闭环 |
|------|----------|----------|
| 接不接产 | 裁决标签 + 确认生产 | 条件接产（订金/改交期）检查清单未结构化 |
| 催哪料 / 保哪单 | 争料展示 + 军师建议 | 一键生成催料任务/分配优先级未接 |
| 今天排谁 | kit_ready + 排产方案 | 「今日 3 件事」→ 一键出方案未打通 |
| 报价留多少 | 实耗偏差提示 | 批价页确认前强制看同类实绩 |
| 放货 / 账期 | 回款 risk 标签（intake） | 出货/放货门禁未接 |
| 质检加严 | quality 指标可查 | 预警条 + 抽检建议未接产线 |

### 总览

```text
P0  A0  今日3件事（看板 + 军师）+ 证据字段
```

技术分层始终：

```text

    → Polars/Pandas（特征与分布）

            → 军师（解释与话术，禁止编数）
```

### P0 / A0 — 今日行动接入证据（下一刀，规则即可）

> **设计一页（契约/UI/任务拆分）：** [`design/A0-today-actions.md`](./design/A0-today-actions.md)

**目标**：军师与工作台出现可点击的「今日 3 件事」，每条带证据，不引入 ML。

| 项 | 做什么 | 验收 |
|----|--------|------|
| `build_today_actions` | 统一 `id` + `evidence{source,facts,order_nos}`；输出 `top3` | 单测：top3≤3、有 facts |
| 权限 | `menu.orders` **或** `menu.schedule` 可查 | 排产角色能打开 |
| 工作台 | 「今日 3 件事」卡片 → `ui_path` | 刷新可见、可跳转 |
| 军师页 | 开场 top3；点击聚焦追问 | 不打开销售单也能看今日 |
| Agent | 只讲 top3，必须引用 evidence | Prompt + 抽样对话 |
| 缺料证据 | 行动上挂已有规则 ETA（若有） | facts 含预计到料/齐套日字样 |

**不做**：sklearn、新报表中心、改库存模型。

**预估**：小迭代（后端 + 看板 + 军师壳）。

### P1a — 齐套预计日 & 订单风险条（特征优先，规则分 → 可换 sklearn）

**目标**：PMC 在缺料/订单上看到「哪天能齐、会不会逾期」。

| 项 | 产品表现 | 数据 |
|----|----------|------|
| 预计齐套日 | 缺料行 / 齐套 Tab / 订单列表列 | 复用并统一 `estimate_material_etas` |
| 交期逾期分 | 订单风险条：绿/黄/红 + 原因 chip | 特征：交期余量、齐套日、急单、负荷占用、进度 |
| 军师 | 问「谁最危险」引用风险分与齐套日 | metric 扩展，禁止口头编日期 |

先规则打分上线；样本够后再 sklearn 校准，**对外仍叫「风险分」**。

### P1b — 批价前「同类款实绩」（Polars）

**目标**：老板/销售批价前 10 秒看到实毛利参照，不只看成本卡。

| 项 | 产品表现 | 入口 |
|----|----------|------|
| 同类款实绩面板 | 历史实耗 vs 成本卡、实毛利中位/分位 | 报价确认前 / 产品成本卡旁 |
| 与 intake 对齐 | 复用/抽离 `_cost_deviation_block`，Polars 聚合大批历史 | 避免两套口径 |
| 军师 | 批价追问只解释面板数字 | 不重复贴大表 |

## 6. 军师产品边界（持续有效）

```text
能做：解释左栏/指标数字、假设对比、写给老板的一句话、建议下一步工具
不能做：编造单号/日期/金额、自动确认生产、自动改派工/交期/采购/工资、替代左栏表格
```

接单布局约定：

| | 左（主） | 右（辅） |
|--|----------|----------|
| 内容 | 结构化诊断 + HITL | 解释 / 追问 / 情景话术 |
| 时延 | &lt;2s | 可后到 |
| AI 关闭 | 完整可用 | 隐藏即可 |

厂级军师页：以 **今日 3 件事开场**，对话为钻取，不做第二个报表中心。

## 9. 八大分析能力 × 阶段映射（对话原文收口）

> 来源：本轮早期「Pandas/Polars 能挖什么」+「sklearn 真正有用的方向」。  
> 首版路线图只在 P3 点名，**此处补全逐条规划**，避免以为「没排」。

### 9.1 分工（再强调）

| 层 | 算什么 | 本系统用法 |
|----|--------|------------|
| SQL / 规则引擎 | 账本、当日可审计结论 | 齐套、利润记账、`schedule_engine` 方案、现有 `analytics.*` |
| Polars / Pandas | 发生了什么 / 分布怎样 | 矩阵、曲线、滚动分位、交叉表、争料、账龄迁移 |
| NumPy | 方案稳不稳 | 到料/产能/不良噪声下的交期违约分布 |
| sklearn | 接下来会怎样 / 该归哪类 / 谁像谁 | 逾期概率、ETA、毛利区间、回款分、负荷预测、质量预警、近邻单 |
| 军师 | 解释与话术 | 只引用指标输出，禁止编数 |

**上线节奏**：先规则分/规则 ETA 进 UI → 同源特征用 Polars 算稳 → 样本够再 sklearn 校准；**对外字段名不变**（仍叫风险分 / 预计齐套日）。

### 9.2 八大能力清单

| # | 能力 | 现状 | 阶段 | 栈 | 产品入口 | 产出 |
|---|------|------|------|----|----------|------|
| **1** | 产能「真值」校准（报工时序） | 配置产能 + 近 14 日粗均；intake 可假设日产能 | **P3**（校准建议可提前用规则喂 top3） | Polars：工序×日×工人矩阵；P50/P90、星期/淡旺季；SKU 学习曲线 | 排产设置、负荷诊断、军师产能校准记忆 | 「可排真实日产能」；插单撞谁更可信 |
| **2** | 瓶颈与流转（捆过站） | 仅瓶颈剩余件数 | **P3** | Polars：`trace_unit_logs` 转移矩阵、停留分布、WIP 年龄、急单 vs 普通流速 | 交期/瓶颈诊断、车间简报 | 「卡在裁还是车」的结构原因 |
| **3** | 质量根因（多维交叉） | `analyze_quality` 工序不良率 | **P2** 预警浅层 → **P3** 交叉/帕累托/冲刺相关 | Polars 交叉表；sklearn 异常检测/分类 | 报工页预警条、质量 brief、今日抽检 | 谁×哪款×什么情境差 |
| **4** | 物料消耗 / 安全库存 / 共用冲突 | 接单争料矩阵 ✅；池分配账本在 `TODO.md` | 争料展示 **Done**；ABC-XYZ/消耗速度/**分配风险分析** → **P3**（不替代齐套正确性） | Polars：消耗速度、提前期分布、等待时长、冲突矩阵 | 缺料/库存池/采购建议；军师「保谁推迟谁」 | 备料策略 + 全局争料风险（分析版，非再算一遍齐套） |
| **5** | 接单与色码结构 | 色码曲线、争料、冲击、情景假设 **Done（规则）** | **Done 主路径**；加强：楦/客户分层、情景表矩阵化、相似单 → **P1a/P3** | 已有规则；Polars 稳曲线；sklearn 近邻 | 销售单生产分析左栏；军师追问 | 偏离提示 + 挤占交期情景 |
| **6** | 利润与报价偏差 | intake 实耗偏差块 ✅；`profit_report` 当期汇总 | **P1b** 批价面板；驱动分解（料/工/不良）→ **P2/P3** | Polars 分布/中位/尾部；分位数回归（可选） | 批价确认前、成本卡旁、经营月报 | 结构性偏差与调价方向 |
| **7** | 回款与客户风险曲线 | intake 回款规则标签 ✅ | **P2** 账龄迁移、放货门禁；逾期概率 → sklearn | Polars 账龄 bucket；分类模型 | 接单、出货/放货前提示 | 「毛利好看但回款差」联合排序 |
| **8** | 排产 what-if / 蒙特卡洛 | 确定性多方案 + 插单仿真 ✅ | **P2** 方案对比卡 + 噪声违约概率 | NumPy 在 `schedule_engine` 方案上加扰动 | 排产页、军师方案解说 | 「方案稳不稳」，不是再出一个确定性方案 |

### 9.3 sklearn 八问 → 阶段与依赖

| 问题 | 模型 | 主要数据 | 产出 | 阶段 | 依赖 / 备注 |
|------|------|----------|------|------|-------------|
| 这单会不会逾期？ | 分类 LogReg/GBDT | 交期、急单、齐套、剩余、历史流转 | 逾期概率 + 排序 | **P1a 规则分 → P3 校准** | 先风险条；有标签后再训 |
| 这料大概哪天齐？ | 回归 | PO 下单→到货、供应商、品类、季节 | ETA 分布 → `earliest_start` | **P1a 规则 ETA → P3 分布** | 已有 `estimate_material_etas` |
| 接这单会不会亏？ | 回归 / 分位回归 | 报价、实耗、不良、加班、客户 | 预估毛利区间 | **P1b 分布 → P2 区间** | 接 cost_deviation |
| 客户会不会拖款？ | 分类 | 账龄、滞后、金额、客户 | 回款风险分 | **P2** | 接单已有粗标签 |
| 哪天/哪工序要爆产能？ | 回归/树 + 时序特征 | `work_logs`、在制、负荷 | 未来 N 日负荷预测 | **P3**（接 #1 真产能） | 配置产能不够信时再上 |
| 不良会不会集中爆发？ | 分类 / 异常检测 | 产量冲刺、款、工人、工序 | 质量预警 | **P2 浅 → P3 深** | 早于「不良率已升高」 |
| 工人/款式怎么分组？ | 聚类 | 人效、擅长工序、不良 | 派工画像 | **P3 可选** | 无标签；慎重上生产派工 |
| 新单像历史上哪几单？ | 近邻 / 度量学习 | 色码、数量、交期松紧、客户 | 类似单当时怎么排、结果如何 | **P3** | 接 #5；军师「参照这几单」 |

### 9.4 与 P0–P3 一句话对照

```text
对话八大能力          落在哪
────────────────────────────────────────
#5 色码/争料/冲击      大半 Done（规则）；强化在 P1a/P3
#6 报价实耗            浅 Done；批价入口 P1b；驱动分解靠后
#4 争料矩阵            接单 Done；ABC-XYZ/消耗 = P3
#7 回款曲线            标签 Done；账龄+放货 = P2
#8 what-if 稳定性      确定性方案 Done；蒙特卡洛 = P2
#3 质量根因            P2 预警 → P3 交叉
#1 真产能              P3（最高杠杆的深分析之一）
#2 过站流转            P3
sklearn 八问           全部挂在上表；无「未规划」项
P0                     不挖新分析，只把已有证据变成「今日 3 件事」
```

### 9.5 明确仍不做

- 用 ML **替代**齐套/库存账本或自动落库排产  
- 无足够历史流水时强行上 sklearn（先规则分占位）  
- 把八大能力做成独立「数据分析子产品」而不挂决策入口  
- 聚类结果直接自动改派工配额

### 10.1 价值排序（PM 判断）

| 优先级 | 能力 | 谁疼 | 为何比花活实 | 难度 | 与现网 |
|--------|------|------|--------------|------|--------|
| **A** | **齐码可发货闸门** | 仓/跟单/PMC | 挡住「末道未齐码就出货 / 不知哪几个码能凑箱」 | 低–中 | 已有色码完工/已出账，出货未卡齐码 |

| **A** | **客供料收货台** | 仓/跟单 | OEM 高频；现有「客供不计成本」规则，缺送来多少/缺多少/催客户 | 中 | 标记已有，无收货单据 |

### 10.2 和「分析路线」怎么排期才不花

建议两条轨并行，**别用分析轨吞掉产线轨**：

```text
轨 A 决策/分析     P0 今日3件事 → P1a 齐套日/风险条 → P1b 批价实绩 → P2 门禁/what-if
轨 B 产线闭环     齐码+生产单流转卡 → 按码BOM → 外发/装箱(P2-Must) → 合批卡(P2-Next) → 真合单(P3闸门)
                 （细节与优先级以 product-roadmap.md 为准）
```

厂若只能再选 **3 个非分析项**：齐码可发货、开裁流转卡、客供收货台。  
色码级 BOM 最正确但最重，宜**单独立项**，不要塞进「军师迭代」。

### 10.3 仍不必挖的（易花）

- 完整 WMS/货位、自动最优分配求解器  
- 蒙特卡洛主界面、工人聚类自动派工  
- 独立「数据分析子产品」门户
