# 垂直竞品「外协 / 外发」模块做法分析

> **范围：** 仅「外协 / 外发 / 委外加工」一域（鞋面底外发、材料委外、工序/制程委外）。
> **对照对象：** 鞋业垂直（小牛、云管家、泛普鞋业）· 通用 ERP 委外（用友/金蝶）作标准参照。
> **本系统锚点：** B2a 外发（路线图本轮跳过）· A2e 实耗损耗预警 · 款成本/成本卡 · 流转卡/扫码报工。

## 1. 竞品如何定义「外协」这件事（切入点）

三家鞋业垂直几乎都把外协定位为**鞋厂第一痛点之一**，且痛点描述高度一致——外协难的根子在**「发出去的东西回不来、回不来多少说不清、损耗算谁的扯不清」**。

| 竞品 | 痛点原文（官网） | 归纳 |
|------|------------------|------|
| 小牛 | 「外发环节多，物料发出与回收无法追踪，**损耗责任难以界定**」 | 追踪 + 损耗责任 |
| 云管家 | 「委外数据难追踪——委外加工直接扫码出库入库」 | 出入库追踪 |
| 通用 ERP（用友/金蝶） | 委外是标准模块，但鞋业色码/损耗按码需二开 | 标准但有缺口 |

对照仓库 `competitive-gap-footwear-erp.md` 既有结论亦印证：**发料 → 收回 → 损耗 → 对账** 是外协的完整价值链，缺一环就「不算鞋厂系统」。

## 2. 核心单据与流程闭环（共性做法）

从官网功能描述反推，垂直竞品的外协模块本质是**一张「外发单」驱动的主单据闭环**：

```text
外发单(下达) → 发料(扫码出库) → 加工(厂外) → 收回(扫码入库)
                                        ↘ 损耗对比(发多少 vs 收多少 vs 标准)
                                        ↘ 欠数追踪(发了没收回的)
                                        ↘ 加工费/对账 → 外加工商应付
                                        ↘ 成本归集到每双鞋
```

| 环节 | 垂直竞品做法 | 关键载体 |
|------|-------------|----------|
| 下达 | 从生产单/工序**自动分单**到外协厂 | 外发加工单 |
| 发料 | **扫码出库**，绑定外协供应商/货号标签 | 条码/PDA |
| 收回 | **委外指令扫码入库，自动生成委外入库单** | 扫码 |
| 损耗 | **损耗率实时对比分析**（实发 vs 实收 vs BOM 标准） | 损耗率 |
| 欠数 | 委外出入库**欠数实时追踪** | 在途量 |
| 对账 | 材料委外 / 工序委外往来对账 → **自动生成外加工商应付报表** | 应付 |
| 成本 | 材料 + 人工 + **外发** + 制造费用归集到每双鞋 | 单双成本 |

## 3. 分厂商拆解（含官网原文）

### 3.1 小牛（niuerp.cn，泉州 · 垂直验货分 8.0）

- 外协是三大产品线（鞋业 / 鞋材 / 鞋底）的**统一模块**，官方命名「外协管控」。
- 官网原文：
  > 「外协管控——鞋面底加工外发全程追踪，损耗率实时对比分析」
- 成本侧官网原文：
  > 「成本核算——材料 + 人工 + 外发 + 制造费用精准归集到每双鞋」

**侧重点：** 追踪 + 损耗 + 成本归集（外发费用是单双成本的四大组成之一）；对账单据细节公开较少。

### 3.2 云管家（ygjsoft.com，温州 · 垂直验货分 7.5）

信息最完整，**把外协拆成三块**：

1. **鞋业 ERP「外协管理」独立模块**（与业务/采购/库存/生产/财务/人事工资并列）。
2. **财务往来**，官网原文：
   > 「通过材料委外往来对账、工序委外往来对账**自动生成外加工商应付报表**」

   关键点：**材料委外（发料出去加工）与工序/制程委外（发工序出去做）是两张账**，对账口径不同。

3. **车间小程序（现场执行）**，官网原文：
   > 「材料委外和制程委外扫码出库；委外指令扫码入库，自动生成委外入库单；**委外出入库和欠数实时追踪**」

另有**供应商 SCM 协同**（把外协厂接入系统），官网原文：
   > 「客户订单审核，可根据货号**自动分单到对应外协订单**到加工厂，加工厂登录 SCM 订单接收、排产、打印流程卡，装箱打包 PDA 扫描下线、入库、发货。实时掌握外加工厂订单生产进度，**自动生成对账单**。」

**侧重点：** 单据完整 + 对账自动 + 小程序扫码 + SCM 让外协厂自报进度。

### 3.3 泛普（fanpusoft.com，营销型 · 垂直验货分 7.7）

- 「**委外执行**」是生产管理下的一等模块，与「生产计划 / 生产订单 / 生产执行」并列。
- 属**通用 ERP 标准委外的鞋业套皮**，无鞋业专属细节（外发损耗、鞋面底外发等），但模块名「委外执行」说明同为「下达-执行-收回」流程化设计。

**侧重点：** 模块齐全 + 流程覆盖；深度存疑（仓库已标注「适合当顾问验收对照，不适合当标杆客户」）。

### 3.4 参照：用友/金蝶标准委外

- 标准「委外订单 + 委外发料 + 委外入库 + 加工费 + 损耗处理」。
- 强在**标准与财务合规**，弱在鞋业语境（色码、鞋面底外发、损耗按码）需二次开发。
- 打法：不拼总账，拼生产执行 ERP + 财务对接。

## 4. 共性架构规律（可直接借鉴的模板）

1. **外协是一张单，不是一句话**：外发单必须有「发料 → 收回 → 损耗 → 欠数 → 对账 → 成本」六段闭环。
2. **材料委外 vs 工序/制程委外必须分开建模**（云管家最清晰）——鞋厂两者都有，且对账口径不同。
3. **条码/PDA 是执行载体**：扫码出库发料、扫码入库收回、自动生成入库单、欠数自动算。
4. **损耗率是外协的灵魂**：发多少 vs 收多少 vs BOM 标准，直接决定「损耗责任该算谁的」。
5. **财务对账自动生成应付**：不是手工记，而是外协单数据流自动生成外加工商应付。
6. **成本归集进单双**：外发费用并入单双成本（小牛），才能回答「这双鞋到底赚不赚钱」。
7. **SCM 协同是二阶能力**（云管家）：外协厂登录接单、自报进度、自动对账——先有主单据再说。

## 5. 与本系统的差距与借鉴落点

**现状：** 本系统外协 0 实现——全仓仅 `schedule_agent.py`/`analysis_plans.py` 把「外协」当仿真假设词。对照 `competitive-scoring-footwear-erp.md`：外发/外协闭环 **1.5 分 vs 垂直均值 8.7 分**，是「验货第一刀」。

**可直接复用的既有资产**（我们的优势，不是从零做）：

| 竞品能力 | 本系统已有可复用 | 差距 |
|----------|------------------|------|
| 损耗率对比 | ✅ A2e 实耗 vs 标准损耗预警（`loss_rate`/`loss_fixed_qty`） | 只差「外发单」挂上发料/收回流水 |
| 成本归集到单双 | ✅ 款成本/成本卡/实耗 | 缺「外发费用」这一成本项 |
| 对账→应付 | ⚠️ 应收/回款/利润有 | 缺外加工商应付 |
| 扫码报工/入库 | ✅ 流转卡/扫码/报工 | 缺「委外出库/入库」扫描动作 |
| 齐套/争料 | ✅ 池互斥 | 外发厂产能未建模（B2a 后） |

**建议落点（对齐路线图 B2a）：**

1. 先建 **外发单**（材料委外 + 工序委外两态），复用现有条码/流转卡。
2. 发料/收回走**扫码出库/入库**，自动生成委外入库单 + **欠数**。
3. 损耗率对比复用 A2e 引擎（发多少 vs 收多少 vs BOM 标准）。
4. 对账自动生成**外加工商应付**，接入现有应收/利润侧。
5. 外发费用并入单双成本。
6. SCM 让外协厂自报进度 + 外协周期进倒排 —— **后置**（B2a+，需主数据 ≥95% 达标，见 `aps-dev-review.md` §2.1）。
